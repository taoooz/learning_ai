# P2 流内答疑第一阶段设计

> 状态：已确认设计，待进入实施计划
> 日期：2026-08-31
> 范围：V2 章节学习流中的最小 Tutor 闭环

## 1. 目标与非目标

### 目标

在不破坏 V2 主任务流的前提下，让用户可以针对当前任务提问，并让问题与 Tutor 回答进入同一条可持久化、可恢复的学习流。

第一阶段采用“流中排队、边界立即回答”：

- 任务流式生成中提问：问题立即入流，主任务继续完成；任务完成后自动回答。
- 任务边界提问：问题立即入流，立即启动 Tutor 流式回答；回答结束后仍停在当前边界。
- 用户必须显式点击继续，才能推进下一任务或完成章节。

### 非目标

- 不实现块间打断和真正的 `partial_paused` 续流。
- 不重写整门课程计划，不让 Tutor 改写 Blueprint 或 Chapter Plan。
- 不复制 V1 ChatWidget 的独立聊天世界。
- 不在 P2 引入开放式能力证据、掌握度结论或 Checkpoint。
- 不并发回答多个问题。

## 2. 数据协议

### 2.1 学习流条目

扩展 `LearningStreamItem`：

```ts
interface UserQuestionItem extends StreamItemBase {
  type: 'user_question';
  itemId: string; // uq:{questionId}
  taskId: string;
  questionId: string;
  text: string;
  status: 'pending' | 'complete' | 'failed';
}

interface TutorAnswerItem extends StreamItemBase {
  type: 'tutor_answer';
  itemId: string; // ta:{questionId}
  taskId: string;
  questionId: string;
  blocks: LearningContentBlock[]; // P2 第一版只允许 markdown
  status: 'pending' | 'streaming' | 'complete' | 'failed';
  errorMessage?: string;
}
```

问题和回答绑定 `chapterId + planVersion + taskId + questionId`。重复事件按确定性 `itemId` upsert，不产生重复条目。

### 2.2 Tutor SSE

沿用现有 SSE 外壳，新增事件类型：

```ts
tutor_started
tutor_block_started
tutor_block_delta
tutor_block_completed
tutor_completed
```

请求错误仍使用 `request_error`，传输收尾使用 `request_completed`。Tutor 事件必须通过 `courseId/chapterId/planVersion/taskId/questionId/requestId` 守卫后才能写入。

### 2.3 运行时字段

复用已有：

- `pendingRequest.kind = 'tutor'`
- `pendingRequest.requestId`
- `scrollAnchorItemId`
- `currentTaskStatus = 'partial_paused'` 继续保留为未来块间打断协议，但 P2 排队路径不伪造该状态。

边界提问期间章节保持 `awaiting_user`，流中排队期间章节保持 `learning` 或正常进入 `awaiting_user`。Tutor 完成不自动推进主线。

## 3. 请求编排

### 3.1 主任务流与 Tutor 流隔离

Hook 维护两套独立的请求控制：

- `taskStreamAbortRef/generationRef`：任务生成和预取。
- `tutorAbortRef/tutorGenerationRef`：Tutor 回答。

Tutor 请求不能复用主任务流的代际计数，也不能取消主任务流。章节切换或卸载时两者都取消；取消只影响未完成请求，不删除已写入的问题。

### 3.2 最小请求上下文

Tutor 请求只发送：

- 课程主题；
- 本章标题与教学目标；
- 当前任务的标题与任务目标（不含 `observableOutcome`：标题加任务目标已构成回答流内问题的最小上下文，不再附带额外字段）；
- 当前任务已完成内容块，按固定字符上限截断；
- 当前任务最近 3 组已完成的问题与回答（范围限当前任务，不含本章其他任务）；
- 当前问题文本与 `questionId`；
- `mode: 'inline_tutor'`；
- 稳定幂等键。

不发送整门课程、V1 ChatWidget 全量历史、过期消息原文或模型思维过程。

### 3.3 问题队列

- 同一章节按提交顺序串行回答。
- 最多 3 个未回答问题进入自动处理窗口；超出部分仍记录，但显示排队提示。
- Tutor 请求进行中不再启动第二个 Tutor 请求。
- 任务完成后从队列取最早的 pending 问题。
- 边界提问优先进入同一队列；若队列空闲立即回答。

## 4. 前端交互

章节页底部常驻轻量输入框，输入框属于学习页而不是 ChatWidget 浮层。

状态表现：

- 提交后立即展示用户问题条目和“正在准备回答…”状态。
- 流中提交时提示“本节内容会先生成完，随后回答你的问题”。
- 边界提交时直接展示 Tutor 流式回答。
- 回答完成后展示“继续本节内容”或“继续学习”按钮；按钮只调用既有主线推进入口。
- Tutor 失败时保留问题，回答条目标记失败，提供“重试回答”，不影响已完成任务和后续主线。
- 中文、错误、断线均保持现有 SSE 行缓冲和 UTF-8 解码策略。

学习流渲染顺序按 `sequence`，问题和回答不从主任务摘要中隐藏。章节完成页保留问题与回答轨迹；Recap 仍是完成卡主展示位。

## 5. 恢复与持久化

### 提交

用户问题是明确学习轨迹，提交后立即持久化一次；不能等待 300ms 节流窗口。

### 流式回答

回答条目增量更新沿用 300ms 节流；Tutor 完成、失败、请求错误立即持久化。

### 刷新

启动时：

- `pending` 或 `streaming` 的 Tutor 回答统一恢复为 `pending`；
- 保留原问题和已展示的回答内容；
- 自动重试一次；
- 重试仍失败则停在失败态，由用户手动重试；
- 已完成回答不重复请求。

任何异步结果写入前必须校验：

`courseId`、`chapterId`、`planId`、`planVersion`、`taskId`、`questionId`、`requestId`。

不匹配的结果丢弃，不污染当前章节。

## 6. 错误处理与安全边界

- 认证、请求参数、章节版本错误由代理层返回明确 HTTP 错误，不写入 Tutor 回答正文。
- LLM 超时、限流、网络断开统一转为用户可见的可重试失败态。
- 不向用户展示上游堆栈、密钥、内部 URL 或思维过程。
- Tutor 只能回答当前课程上下文，不修改章节计划、课程路线或持久化证据。
- 与课程无关的问题允许简短回答并引导回当前任务，不改变主线。
- 章节切换、卸载、重复点击均由 requestId/generation/idempotency 守卫处理。

## 7. 实现边界

预计改动范围：

- `types/learning-v2/learning-stream.ts`：新增问题/回答条目；
- `types/learning-v2/events.ts`：新增 Tutor 事件与载荷；
- `lib/learning-v2/reducers.ts`：问题、回答和 Tutor 事件归约；
- `lib/learning-v2/state-machine.ts`：只补齐 P2 实际需要的合法转换；
- `hooks/learning-v2/useChapterLearning.ts`：Tutor 队列、请求隔离、恢复、持久化；
- `components/learning-v2/`：问题输入、问题/回答渲染、边界操作；
- `app/api/learning/v2/` 或现有 Chat 代理：V2 Tutor 薄透传；
- `python-agent/`：最小 Tutor 请求模型、Prompt 和 SSE 服务；
- 对应 TS/Python 测试与 CHANGELOG。

不改 V1 课程页和现有独立 ChatWidget 的用户流程。

## 8. 验证标准

### 协议与纯函数

- 问题提交立即入流且幂等；
- Tutor delta 按 blockId 累积，中文任意切分不乱码；
- 事件版本、章节、任务、问题和请求 ID 不匹配时拒绝写入；
- 回答完成/失败状态正确，重复事件不漂移 sequence；
- 已回答问题不重复触发请求。

### 交互与恢复

- 边界提问立即回答，回答后仍停在边界；
- 流中提问不取消任务流，任务完成后自动回答；
- 多问题串行处理，最多 3 个未回答问题有明确提示；
- 刷新后 pending/streaming Tutor 请求自动重试一次；
- Tutor 失败可局部重试，不影响任务内容；
- 卸载或章节切换不会把旧回答写入新章节。

### 回归

- TypeScript 测试、Python 测试、typecheck、lint 全部通过；
- V1 ChatWidget 流程无回归；
- 真实 LLM 冒烟确认中文流式回答、错误路径和鉴权路径。
