# 课程生成逻辑（全链路）

## 全局视角

课程生成是一个**记忆驱动的渐进个性化**流程。用户每学一次，记忆系统就更了解他，下一轮课程就更有针对性。链路分四步：

```
用户输入主题
    ↓
Outline：搞清楚"学什么、学到什么程度"（可能先提问澄清）
    ↓
TOC：决定"怎么组织内容"（选课程框架 + 每个章节选教学策略）
    ↓
Cards：生成知识卡片（根据用户水平和薄弱点调整深度和类比）
    ↓
Questions：出练习题（根据水平调难度，根据薄弱点调考查重点）
```

每一步都接收**记忆系统**的输入，粒度从粗到细：Planning（宏观水平/可跳过什么）→ Teaching（具体概念的掌握度和误区）。

---

## 一、Outline 阶段：决定课程定位

### 目标
从用户的一句话描述，产出一份课程蓝图（Blueprint），明确课程的方向、重点、目标、用户定位。

### 输入

| 输入 | 来源 | 业务作用 |
|------|------|---------|
| topic | 用户原始输入 | 学习诉求的起点 |
| 用户画像 | 画像系统 | 目标岗位、工作/教育背景、类比经历、学习风格、技术接受度 |
| Planning 记忆 | 记忆系统 | 用户当前水平、必须覆盖的概念、可跳过的基础、高风险误区、近期课程（去重用） |

### 核心决策

**1. 提问还是直接生成？**

由 LLM 自主判断。规则：信息不足时才提问，否则直接出蓝图。

提问约束：
- 每次仅 1 个问题，累计最多 3 个
- 格式固定为单选题（4 选项），降低回答成本

**2. 需求穿透**

不只是字面理解用户说了什么，而是思考用户**潜在的实际需求**。比如用户说"学 AI"，可能真正需要的是"用 AI 提升工作效率"而非"理解 Transformer 架构"。

**3. 设计重点选择**

从 8 个维度中选 2-5 个作为课程重点：
概念解析 / 原理机制 / 实践应用 / 商业价值 / 发展趋势 / 成本效益 / 对比辨析 / 决策策略

### 蓝图产出

| 字段 | 业务含义 | 约束 |
|------|---------|------|
| learningDirection | 课程定位：范围概括 | 30 字内 |
| learningKeypoint | 课程重点：内容重心 | 40 字内 |
| learningGoal | 学完能达到什么效果 | 50 字内，具体不务虚 |
| estimatedLevel | 用户当前水平 | 初级/中级/高级 |
| backgroundSummary | 用户相关背景 | 有则标注，影响内容起点 |
| skipBasics | 已掌握可跳过的知识 | 有则标注，TOC 阶段不再单独成章 |
| difficultySummary | 难度定位说明 | 描述性 |
| whyThisCourseFits | 为什么适合该用户 | 解释课程与用户的匹配逻辑 |

### 记忆如何影响蓝图

| 记忆输入 | 对蓝图的影响 |
|---------|------------|
| mustCoverConcepts（learning/fragile 状态的概念） | 保证课程必含这些概念 |
| skippableBasics（mastered 状态的概念） | 标记为可跳过，不浪费篇幅 |
| riskConcepts（有错误记录或误区的概念） | 需重点关注的易混淆点 |
| transferableBackground（类比经历/知识背景） | 可用于类比教学 |
| recentRelevantCourses | 避免与近期课程重复 |
| estimatedLevel | 决定课程起点高低 |

## 二、TOC 阶段：决定内容组织方式

### 目标
从蓝图出发，选择课程框架和每个章节的教学策略，产出章节目录。

### 输入

| 输入 | 来源 | 业务作用 |
|------|------|---------|
| Blueprint | Outline 产出 | 课程定位和用户水平 |
| 用户画像 | 画像系统 | 同 Outline |
| Planning 记忆 | 记忆系统 | 近期课程（去重） |

### 核心决策 1：选哪种课程框架

8 种课程框架，各有适用场景。LLM 根据主题性质和用户情况选择。

| 框架 | 核心逻辑 | 最适合 |
|------|---------|--------|
| **渐进深入** | 基础概念 → 核心原理 → 高级应用 | 完整入门路径，初学者优先选 |
| **问题驱动** | 问题定义 → 拆解归因 → 解决方案 → 落地 → 避坑 | 用户有明确痛点 |
| **系统拆解** | 总-分-总，逐模块深入后综合串联 | 复杂领域，各模块相对独立 |
| **对比辨析** | 统一维度对比多方案 → 差异 → 优劣势 → 选型 | 选型决策场景 |
| **演进历程** | 诞生 → 发展 → 迭代 → 未来趋势 | 技术演进史、行业变革 |
| **案例驱动** | 真实案例为主线，在拆解中串联知识 | 实战型学习 |
| **理论实践** | 每个知识点配套独立练习 | 技能型学习，需动手 |
| **项目实战** | 所有知识点服务一个完整项目 | 项目驱动的综合实战 |

### 核心决策 2：每个章节选哪种教学策略

每个章节独立选择一种节点框架（frame），决定该章节的内容组织方式。

| 节点框架 | 内容组织方式 | 教学意图 |
|---------|------------|---------|
| **是什么-为什么-怎么做** | 概念引入 → 价值 → 应用 | 概念入门类章节 |
| **总-分-总** | 一句话核心 → 拆解细节 → 结构化总结 | 信息密集型，帮快速建结构 |
| **步骤拆解** | 目标 → 步骤 → 验证 → 避坑 | 纯操作流程，照着做 |
| **案例复盘** | 案例背景 → 执行过程 → 关键决策 → 方法论 | 从具体到抽象 |
| **问题-方案** | 问题定义 → 根源拆解 → 方案设计 → 落地验证 | 导向明确地解决问题 |
| **对比分析** | 统一评判维度 → 核心差异 → 优劣势 → 适用边界 | 帮助做选择和判断 |
| **时间线演进** | 发展阶段 → 关键节点 → 驱动因素 → 未来趋势 | 建立历史纵深感 |
| **探索-推导** | 核心疑问 → 假设推导 → 规律总结 → 延伸探索 | 引导自主思考 |

### 节点规模与质量约束

- 节点数量：5-15 个
- 课程名称：10 字内
- 章节标题：25 字内，避免过度概括
- 章节描述：至少 2 个具体知识点/技能 + 学完后能做的一件具体的事
- 禁止空泛表述（"深入了解""掌握核心""全面了解"等）
- 已掌握知识点不单独成章，可作为复习提及

## 三、Cards 阶段：生成知识卡片

### 目标
为每个章节生成 5-8 张知识卡片，内容深度和风格随用户水平、掌握度、偏好动态调整。

### 输入

| 输入 | 来源 | 业务作用 |
|------|------|---------|
| 章节信息 | TOC 节点 | 标题、教学目标、节点框架 |
| 前后章节 | TOC | 避免重复、做好铺垫衔接 |
| 用户水平/背景 | Blueprint | 决定内容起点和术语密度 |
| 可跳过知识 | Blueprint | 压缩已掌握内容 |
| 用户偏好 | 画像 | 学习风格（理论/实践）、技术接受度、价值关注点 |
| Teaching 记忆 | 记忆系统 | 具体概念的掌握度、误区、类比、偏好解释方式 |

### 核心决策 1：内容深度随水平调整

| 水平 | 深度策略 |
|------|---------|
| 零基础 | 从核心概念讲起，低门槛搭建基础认知 |
| 有基础 | 聚焦实战应用、场景化方案与实操技巧 |
| 有成熟经验 | 聚焦底层原理、复杂场景与进阶决策 |

技术接受度额外调节术语密度：

| 技术接受度 | 术语策略 |
|-----------|---------|
| 入门级 | 避免未解释的专业词汇，用日常类比 |
| 业务级 | 常见术语直接用，专业术语需解释 |
| 专家型 | 自由使用专业术语和代码，聚焦深度 |

### 核心决策 2：教学记忆如何影响卡片

| 记忆信号 | 卡片策略 |
|---------|---------|
| 前置概念掌握度 < 0.6 | 补充前置知识，防止知识断层 |
| 目标概念有 misconceptionHints | 增加误区辨析和反例 |
| 用户最近提过相关问题 | 在内容中回应困惑 |
| 有可用类比（用户背景相关） | 优先用用户熟悉的场景举例 |
| 有偏好解释方式 | 按偏好风格组织内容 |

### 核心决策 3：可视化是否添加

**克制原则**：确实能帮助理解时才输出，不确定结构是否正确就不输出。

| 类型 | 适用场景 |
|------|---------|
| flowchart | 步骤、流程、判断路径 |
| timeline | 时间顺序、阶段演进 |
| comparison | 多方案对比 |
| table | 分类整理、参数汇总 |
| keyPoints | 核心结论、判断原则、记忆要点 |

### 卡片质量标准

- 每张 200 字以内，围绕一个知识或技能
- "如果 Google 搜索摘要里随便就能看到，就不要写"
- 去掉任何删掉后读者没有损失的话
- 读者是有经验的职场人，内容必须有实际价值

## 四、Questions 阶段：出练习题

### 目标
为每个章节出 3-5 道题，覆盖多维度、有难度梯度，薄弱点多考。

### 输入

| 输入 | 来源 | 业务作用 |
|------|------|---------|
| 章节信息 | TOC | 章节名、目标 |
| 全部卡片内容 | Cards 阶段 | 题目的知识来源 |
| 用户水平/背景 | Blueprint + 画像 | 调整难度、场景选择 |
| 可跳过知识 | Blueprint | 不考已掌握的基础 |

### 题型分配策略

| 题型 | 数量约束 | 说明 |
|------|---------|------|
| 单选题 | 至少 1 道 | 4 选项 |
| 多选题 | 至少 1 道 | 4+ 选项，至少 2 个正确 |
| 填空题 | 可选 | 含 `___` 空位的完整句，4-6 个候选词 |

### 维度覆盖策略

4 个考查维度，同一维度不超过 2 道，尽量覆盖多个：

| 维度 | 考什么 |
|------|-------|
| 记忆 | 概念、定义、事实的准确记忆 |
| 理解 | 原理、因果关系的理解 |
| 应用 | 在场景中运用知识 |
| 分析 | 拆解、对比、评估 |

### 难度梯度策略

| 难度 | 含义 | 何时多出 |
|------|------|---------|
| 1 | 直接从内容找到答案 | 水平低时居多 |
| 2 | 需理解和推理 | 均衡分布 |
| 3 | 综合分析和场景应用 | 水平高时居多 |

### 出题质量约束

- 干扰项要有迷惑性，不能一眼看出对错
- 题干用自然语言，避免生硬术语
- 填空题的句子要完整自然，候选词有干扰性
- 如有用户薄弱概念，至少 1 道题直接考查

## 五、记忆系统：驱动个性化的引擎

记忆系统在课程生成中提供三种 Payload，粒度从粗到细：

### Planning Payload（Outline/TOC 阶段用）

回答"这个用户是谁、已经会什么、必须学什么"。

| 字段 | 筛选逻辑 | 业务意图 |
|------|---------|---------|
| learnerSnapshot | 取最相关主题的 estimatedLevel；无数据默认 novice | 决定课程起点 |
| mustCoverConcepts | 状态为 learning/fragile 的概念，最多 3 个 | 保证覆盖薄弱点 |
| skippableBasics | 状态为 mastered 的概念，最多 2 个 | 避免浪费时间 |
| riskConcepts | 有错误记录或误区的概念，最多 3 个 | 重点关注易混淆点 |
| transferableBackground | 与主题相关的类比经历/知识背景，最多 3 条 | 可用于类比教学 |
| recentRelevantCourses | 主题相关性×0.6 + 新鲜度×0.4，>=0.3，最多 3 门 | 避免重复 |

### Teaching Payload（Cards/Questions 阶段用）

回答"这个章节涉及什么概念、学生掌握到什么程度、有哪些误区"。

| 字段 | 筛选逻辑 | 业务意图 |
|------|---------|---------|
| prerequisiteConceptStates | 掌握度 < 0.6 的前置概念，最多 3 个 | 补知识断层 |
| targetConceptStates | 按掌握度升序取最薄弱的，最多 3 个 | 教学重点对准薄弱点 |
| recentQuestionSummaries | 最近相关提问，最多 3 条 | 回应用户困惑 |
| analogyHints | 与主题+章节相关的类比，最多 3 条 | 用熟悉场景帮助理解 |
| preferredExplanationStyles | 预留（当前为空） | 按偏好风格讲解 |

### Chat Payload（聊天辅导用）

回答"用户现在聚焦什么、有什么风险"。

| 字段 | 筛选逻辑 |
|------|---------|
| focusConceptStates | 以当前章节/题目为焦点取 top-3 概念 |
| riskConcepts | 有错误或误区的概念；无数据则回退到焦点概念 |
| learningSummary | 整体学习旅程总结 |

### 概念相关性评分

检索概念时的排序公式：
```
score = 主题相关性 × 0.5 + 衰减后掌握度 × 0.3 + 新鲜度 × 0.2
```

50% 看相关性，30% 看掌握状态，20% 看时效。

## 六、关键设计思想

| 设计 | 策略 | 意图 |
|------|------|------|
| 提问克制 | 最多 3 问，每次 1 问，单选格式 | 降低流失 |
| 可视化克制 | 确实有帮助才加 | 避免信息噪音 |
| 答错权重大于答对 | -0.22 vs +0.18 | 宁可低估掌握度，不让用户跳过关键内容 |
| 记忆粒度递进 | Planning 粗（水平/可跳过）→ Teaching 细（具体概念误区） | 先规划后教学 |
| 节点完成 ≠ 掌握 | 完成节点 mastery 只升到 0.62（fragile） | 需要答题验证才算真正掌握 |
| mastered 双条件 | 分数 ≥ 0.78 且无近期错误 | 防止"曾经会但现在忘了"被误判 |
