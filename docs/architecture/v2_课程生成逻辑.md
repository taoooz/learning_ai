# 课程生成逻辑 v2（全链路）

> 与 v1 的核心区别：增加 `intent_type` 显式建模 + `learningObjectives` 取代章节描述 + **ChapterPlan + Director Agent 取代 Cards + Questions**。章节内由用户主导节奏，AI 在背后动态调整后续任务。

---

## 全局视角

```
用户输入主题
    ↓
Outline：定课程方向 + intent_type
    ↓
TOC：定章节框架（每章带 learningObjectives）
    ↓
进入章节 N
    ↓
Planner Agent：生成 ChapterPlan v1（task 元数据 + Task 1 内容）
    ↓        ↘
显示 Task 1   后台预取 Task 2
    ↓
┌─ 用户行为分支 ─────────────────────────┐
│ 直接「下一步」→ 推进                    │
│ 输入框提问 → Director Agent → 6 action │
└────────────────────────────────────────┘
    ↓ 全部 task 完成
Recap：聚合信号 → 更新 L1/L2 画像 → 解锁下一章
```

---

## 一、Outline 阶段（v1 + intent 字段）

### 目标
与 v1 一致，但额外输出 `intent_type` 字段，作为后续 TOC/ChapterPlan/Director Agent 的共享上下文。

### 新增字段：intent_type

| 意图 | 触发特征 | 教学重心 | 默认教学策略偏好 |
|------|---------|---------|----------------|
| `concept_understanding` | "原理""为什么""本质" | 定义→关系→反例 | 解释类策略为主 |
| `skill_mastery` | "怎么做""上手""操作" | 步骤→演练→checklist | 步骤+演练策略为主 |
| `problem_solving` | 含 bug/痛点/具体场景 | 诊断→根因→方案 | 案例+原理推导 |
| `fast_review` | "总结""复习""重点" | 高密度要点 | 浓缩复习 |
| `decision_support` | "选哪个""对比""值不值" | 维度→对比→选型 | 对比+决策 |

由 LLM 在 Outline 同一次调用中输出，不增加额外 LLM 成本。

### 提问规则、Blueprint 字段
与 v1 一致（learningDirection / learningKeypoint / learningGoal / estimatedLevel / backgroundSummary / skipBasics / difficultySummary / whyThisCourseFits）。

---

## 二、TOC 阶段（v1 + learningObjectives）

### 目标
与 v1 一致，但**每章描述拆为 `learningObjectives[]`**，作为 ChapterPlan 的输入。

### 新结构

```ts
ChapterNode {
  id, title (≤25字),
  frame: NodeFrame,                        // v1 的 8 种教学策略，保留
  learningObjectives: string[]             // 2-4 条可观测目标，动词开头
  description?: string                     // 兼容字段，可逐步废弃
  conceptRefs: string[]                    // 涉及概念（来自 Outline.mustCover/Blueprint）
}
```

### learningObjectives 写作规则

- 必须用动词开头（说清/能判断/识别/对比/能做到）
- 必须可观测（用户能自我验证是否达到）
- 一章 2–4 条，每条 15–30 字
- 不要务虚（避免"深入理解""掌握核心"）

示例：
```
章节"理解 RAG 的检索阶段"
learningObjectives:
  - 说清向量检索与关键词检索的差异
  - 能判断什么场景该用 hybrid 检索
  - 识别 top_k 设置错误的典型症状
```

### 8 种课程框架、节点框架
完全保留 v1 设计。`frame` 字段仅作为 ChapterPlan 生成时的策略提示，不再直接决定卡片结构。

---

## 三、ChapterPlan 阶段 ★（取代 v1 的 Cards 阶段）

### 目标
章节进入时，生成一份"章节任务规划"：3–7 个 task 的元数据 + 仅 Task 1 的完整内容。其余 task 内容按需生成（含预取）。

### 数据结构

```ts
ChapterPlan {
  chapterId
  version: number                       // 每次 revise/insert +1
  objectives: string[]                  // 来自 TOC.learningObjectives
  tasks: Task[]                         // 3-7 个
  state: 'initial' | 'adapting' | 'completed'
  estimatedMinutes: number
}

Task {
  id
  goal: string                          // 这个 task 要达到的具体目标
  conceptRefs: string[]                 // 涉及概念
  predecessorIds: string[]              // 依赖（v1 用线性，预留 DAG）
  content: MarkdownBlock[] | null       // null 表示未生成
  metadata: {
    estimatedReadSeconds
    visualHints?: ('flowchart'|'comparison'|'timeline'|'table'|'keyPoints')[]
    originatedBy: 'initial_plan' | 'remediation' | 'expansion' | 'revision'
    coversObjectiveIds: string[]
  }
  status: 'locked' | 'active' | 'done'
  generatedAt, version
}
```

注意：
- **没有独立的 check_in 字段**。每个 task 后默认就是「下一步 + 输入框」交互。
- **没有 type 字段**。教学策略沉淀到内容生成 prompt 内部。

### Planner Agent 输入

| 输入 | 来源 | 业务作用 |
|------|------|---------|
| chapter 元数据 | TOC | 标题、目标、frame |
| learningObjectives | TOC | 任务拆解依据 |
| Blueprint | Outline | 用户水平、intent、skip/mustCover |
| L1 画像 Planning Payload | 记忆系统 | concept 状态、可用类比、偏好 |
| L2 上一章遗留状态 | 章节运行时 | 未充分覆盖的目标、emerging 偏好 |
| recentTaskHistory（本课程内） | 章节运行时 | 避免重复 |

### Planner Agent 输出约束

```
1. task 数量 3-7（按章节复杂度）
2. task 顺序必须渐进：从认知前提 → 核心 → 应用 → 收束
3. 每个 task.goal 必须可在 1 屏（≤200 字 + ≤1 图 + ≤1 代码块）内交付
4. objectives 必须被全部覆盖（每个 objective 至少有 1 个 task.coversObjectiveIds 包含它）
5. skipBasics 列表中的概念不单独成 task（可作为前置一句话提及）
6. mustCoverConcepts 必须显式纳入 task.conceptRefs
7. 输出 task 元数据 + 仅 Task 1 的完整 content
```

### Task 内容生成的隐式教学策略

LLM 根据 `task.goal` 性质在 prompt 内部自适应选择策略（用户不可见）：

| 目标性质 | 内容内化策略 |
|---------|------------|
| 解释概念 | 定义 → 直观类比 → 反例/边界 |
| 教操作 | 上下文 → 步骤 → 验证点 → 避坑 |
| 帮决策 | 关键维度 → 对比 → 适用边界 |
| 复盘案例 | 案例 → 关键决策 → 抽出原理 |
| 衔接/导入 | 上一节结论 → 本节痛点 → 路线图 |
| 综合应用 | 给场景 → 引导先想 → 揭示分析路径 |

### Task 末尾的"软引导"（借鉴 Hyperlearn）

每个 task 内容末尾允许 LLM 自由生成 1 句"想一想：……" 的引导句，**不强制回答**。提升认知粘性，但不阻塞推进。

### Cards 生成的个性化调节（保留 v1）

水平、技术接受度、学习风格、价值关注点、可跳过知识、必须覆盖概念、风险概念、可用类比、解释偏好——这些在 ChapterPlan 的 task 内容生成 prompt 中继续生效。

### 可视化的克制原则（保留 v1）

flowchart / timeline / comparison / table / keyPoints 五类。"确实能帮助理解时才输出"。`task.metadata.visualHints` 由 LLM 自主决定。

## 四、Director Agent ★（取代 v1 的 Questions + ChatPanel）

### 目标
章节内每条用户输入触发一次。**LLM 单次调用**，返回 6 种 action 之一 + 参数。

### 触发时机

| 触发 | 处理 |
|------|------|
| 用户在输入框提交文字 | 必触发 |
| 用户点"下一步"（输入框为空） | 不触发 Director，直接推进 |
| 用户点"下一步"（输入框有未提交内容） | 提示"还有未发送的疑问，是否一起发送？" |
| 用户停顿超过预估时长 1.5× | 触发 Director（带 `signal: 'long_pause'`），可主动 expand_here 抛反例 |

### Action 设计

| Action | 触发场景 | 参数 | UI 效果 | 副作用 |
|--------|---------|------|--------|--------|
| `inline_answer` | 30 字内能说清 | `{ text }` | 输入框上方气泡 | episode 记录 |
| `expand_here` | 想深入/再举例 | `{ focus, style }` → 调 gen_task_content | 当前 task 下方追加内容 | L2 标记 expand 概念 |
| `insert_task` | 前置缺口/补救 | `{ goal, conceptRefs, position }` | 进度条 +1，下一步进新 task | mastery 限制 ≤0.4 |
| `revise_plan` | 改变方向 | `{ operations: [{remove\|add\|reorder\|change_depth}] }` | task 序列更新，提示"已根据反馈调整" | ChapterPlan.version +1 |
| `note_signal` | 情绪/偏好 | `{ kind, evidence }` | 轻量确认气泡 | L2 emergingPreferences / confusionMarkers |
| `proceed` | "懂了"/"继续" | - | 推进下一 task | mastery 顺利信号 |

### Director Agent 的 system prompt 要点

```
你是一个学习导演 Agent。用户正在学习章节"{chapter.title}"，
当前 Task: {task.goal}。你的目标是让用户在不打断学习节奏的前提下
得到回应。

判断规则：
- 30 字内能说清 → inline_answer
- 涉及当前 task 的概念深入 → expand_here
- 涉及前置知识缺口 → insert_task
- 改变学习方向（跳过/补充/换重点）→ revise_plan
- 仅是表达情绪/偏好/进度感受 → note_signal
- 显式说"懂了/继续/下一步" → proceed

保守原则：
- 不确定时优先 inline_answer
- 一节课内 revise_plan 不超过 2 次
- insert_task 后该章节剩余 task 数量上限 = 原 7 个
- 输出前必须有 thought 字段（不展示给用户，仅用于调试）

context：
- chapter.objectives
- chapterPlan.tasks[].goal
- L1 Planning Payload（用户水平、可跳过、必须覆盖）
- L2 ChapterRuntimeState（本章节内的进度/困惑/偏好）
- 最近 3 个 task 的内容摘要
- 用户当前输入
```

### Director Agent 的输入 Payload

```ts
DirectorPayload {
  chapter: { id, title, objectives[] }
  plan: { tasks: { id, goal, status }[], version }
  currentTask: { id, goal, content_excerpt }
  recentTaskHistory: { id, goal, durationMs, userMessages[] }[]
  L1: PlanningPayload (来自 V3 记忆系统)
  L2: ChapterRuntimeState
  userMessage: string | null
  signal?: 'long_pause' | 'explicit_skip'
}
```

### Director Agent 的输出格式

```json
{
  "thought": "用户问的是 RAG 和向量检索差异，属于当前 task 概念深入，且 30 字答不清，应该 expand_here",
  "action": "expand_here",
  "params": {
    "focus": "RAG 流程 vs 纯向量检索的差异",
    "style": "用类比 + 一图对比"
  },
  "noteToMemory": {
    "kind": "confusion",
    "conceptRefs": ["RAG", "vector_retrieval"]
  }
}
```

## 五、Recap 阶段 ★（取代 v1 的章节末小测）

### 目标
章节最后一个 task 完成后，触发 Recap。**不再有强验证题目**。

### Recap 内容

```
✅ 本章你掌握了：[list 顺利通过且无困惑的概念]
⚠️  还需要巩固：[list 触发过 expand/insert 的概念]
📌 我们调整过：[list 本章 revise_plan / insert_task 次数与原因]
👉 下一章预告：[next chapter title + 1 句话铺垫]
```

由 LLM 单次调用生成，输入是 ChapterRuntimeState + L1 摘要。

### Recap 触发的副作用

1. **Memory Updater**：将 L2 状态聚合写入 L1（详见 v2_用户画像维护逻辑.md）
2. **LLM 精炼**：触发一次 learningSummary 更新（与 v1 一致）
3. **L2 清理**：本章 ChapterRuntimeState 归档为 episodic，新章节重新创建 L2

## 六、工具与 Agent 架构

### Agent 列表

| Agent | 触发时机 | LLM 调用 | 主要工具 |
|-------|---------|---------|---------|
| Planner Agent | 章节进入 | 1 次 | gen_plan, gen_task_content |
| Director Agent | 用户每次提问/长停顿 | 1 次 | 路由到 6 个 action 工具 |
| Memory Updater | task done / Recap | 0 次（规则）+ Recap 时 1 次（精炼） | mastery_aggregator |
| Recap Agent | 章节最后 task done | 1 次 | - |

### 工具列表

| 工具 | 调用方 | 输入 | 输出 |
|------|--------|------|------|
| `gen_plan` | Planner | chapter + L1 + L2 | ChapterPlan v1 + Task 1 content |
| `gen_task_content` | Planner / Director.insert_task / Director.expand_here | task.goal + context | MarkdownBlock[] |
| `revise_plan_tool` | Director.revise_plan | operations[] | new ChapterPlan |
| `search_web` | gen_task_content 内部 | query | results（保留现有 Agent 搜索） |
| `gen_visual_hint` | gen_task_content 内部 | content | visualHints[] |
| `mastery_aggregator` | Recap 阶段 | L2 + taskHistory | 写入 L1 概念分 |
| `gen_recap` | Recap Agent | L2 summary | Recap markdown |

### API 路由

| 路由 | 用途 |
|------|------|
| `POST /api/chapter-plan` | 章节进入：返回 v1 plan + Task 1 内容 |
| `POST /api/chapter-plan/task` | 按需生成 Task N 内容（用户点下一步前的预取也走此） |
| `POST /api/director-agent` | 用户输入或长停顿信号 → action |
| `POST /api/chapter-recap` | 最后 task done → 触发 Recap + 画像更新 |

### 废弃的 v1 路由 / 模块

- `/api/cards` / `/api/questions` → 合并入 chapter-plan 流
- `ChatPanel` 弹窗式入口 → 改为底部常驻输入框
- "深入理解" / "为什么错了" 快捷入口 → Director Agent 智能判断替代

## 七、关键设计思想（v2 修订）

| 设计 | 策略 | 意图 |
|------|------|------|
| 用户节奏主导 | 「下一步」+ 输入框 | 不强迫看完所有，自适应推进 |
| 任务规划按需生成 | v1 全章 task 元数据 + 预取下一 task | 首屏快 + 中途可调整 |
| Director Agent 保守 | 一节内 revise_plan ≤ 2 次 | 防止频繁改 plan 让用户迷失 |
| 不暴露 task 类型 | 教学策略沉淀到 prompt 内部 | 用户视角统一为"教学内容" |
| 取消章末小测 | mastery 完全靠过程信号 | 体验连贯，但要求过程信号设计严密 |
| 软引导而非硬验证 | task 末尾"想一想：……" | 提认知粘性不阻塞 |
| thought 字段强制 | Director Agent 必须先输出 thought | 可解释、可调试、可作为下次优化依据 |
| 三层画像 | L1 长期 / L2 章节 / L3 任务 | L2 缓冲避免单次状态污染长期画像 |

## 八、迁移与灰度建议

1. **v1/v2 双跑**：保留 v1 cards/questions 路由，新增 v2 路由；用 feature flag 切换。
2. **试点章节**：先在系统课"AI 实战进阶课"上启用 v2。
3. **关键指标对比**：完成率、单章节平均时长、用户提问次数、Director.revise_plan 频次、mastery 收敛速度。
4. **回退预案**：v2 出现 Director 误判率 >15% 或 task 重生成 >3 次/章 → 切回 v1。
5. **数据迁移**：旧 cards/questions 记录归档为 episodic，不再展示但保留分析。
