## 1. 架构分层

```text
Browser
  ├── Next.js App Router（UI + 状态编排）
  │     ├── hooks/learning-v2/*       章节学习编排
  │     ├── lib/learning-v2/*        V2 协议、状态、存储抽象
  │     └── app/api/*                BFF 薄代理
  └── Next API → Python FastAPI Agent
        ├── routers/learning_v2.py    学习流生成 API
        ├── routers/user_data.py      用户数据 API
        ├── services/*                LLM 编排、校验、解析
        └── lib/minimax*.py           OpenAI 兼容客户端
```

要点：

- Next API 只做鉴权、参数校验、服务间认证和转发，不承载教学业务。
- Python Agent 负责大纲、目录、章节计划、任务内容、答疑、检查点、补救和总结。
- 前端是学习状态的事实来源，服务端保存用户数据但不做实时协同。

## 2. 当前数据流

### 课程创建

```text
/generate/chat
  → /api/agents/outline
  → Python Agent outline/generate_agent
  → /generate/toc
  → /api/generate/toc
  → Python Agent toc/generate_agent
  → mapTocToBlueprintV2
  → validateCourseBlueprintV2
  → createAndSaveStoredCourseV2
  → /course/{courseId}
```

- V1 节点学习流已下线。
- Outline 会派生 `CourseMission`（why、目标场景、成功标准、约束、非目标）并注入 TOC 生成。
- TOC 结果只写 `StoredCourseV2`；蓝图同时持久化 mission。
- 蓝图校验失败、空目录或落盘失败直接报错，不降级、不半写。

### 章节学习

```text
/course/{courseId}/chapter/{chapterId}
  → useChapterLearning
  → /api/learning/v2/chapters/plan
  → /api/learning/v2/tasks/stream
  → LearningStreamV2
  → checkpoint / tutor / remediation / plan patch
  → recap
  → completeChapterV2
```

- 章节计划按需生成；最后一个任务由服务端强制 `evidencePolicy=checkpoint`。
- 任务内容 SSE 流式输出；任务、提问、检查点、补救和总结都进入 `NodeLessonV2.streamItems`。
- 章节完成时把 Checkpoint 评估投影为 `checkpoint_evaluated` memory event。
- 章节完成后从 key_point / comparison / diagram 提取课程速查卡和统一术语，并更新课程级教学状态。
- 章节计划与任务内容 prompt 会接收教学状态中的待反馈材料和可复用素材。
- 章节解锁由章节真实完成状态派生，不信任课程树缓存。

## 3. 存储现状

模式由 `NEXT_PUBLIC_LESSON_STORE` 控制，默认 `local`。

### local

```text
localStorage
  ├── ai-learning-data-v2[:inviteCode]
  │     └── v2Courses: StoredCourseV2[]
  └── ai-learning-data-v2[:inviteCode]:course:{courseId}:chapter:{chapterId}
        └── NodeLessonV2
```

### server

```text
Next API
  └── Python Agent /api/user/*
        └── python-agent/data/user_data/{accountId}/
              ├── courses.json
              ├── lessons/{courseId}__{chapterId}.json
              └── engagement/{courseId}.jsonl
```

- server 保存成功后写本地镜像。
- server miss 时回退本地缓存，保证网络故障不挡用户。
- 课程读取时按章节事实自愈 `treeView`。
- 课程删除同时清理课程、章节和 engagement；本地章节 key 同步清理。

## 5. 与 V2 长期规格的关系

- V2 三份长期规格定义目标架构和阶段边界，仍然有参考价值。
- P0～P5 的主要能力已经落地，但不是所有目标细节都等同于当前实现。
- 服务端持久化已按 `LessonRepository` 方向落地，不是完整多设备实时协同。
- 证据系统已用于任务内容、Checkpoint、补救和 Memory 投影；下一步可做跨日复习调度。
- 动态调度有计划补丁建议，但受白名单、证据强度和每章补丁上限约束。

因此：

1. 修改当前行为时，以本文和交接包为准。
2. 设计新能力时，可回看 V2 长期规格。
3. 不要把长期规格中的未来能力当作已存在功能。

## 6. 主要工程约束

- 用户可见文本全部中文。
- 新课程不得写 V1 `courses` 容器。
- `CourseBlueprintV2` 必须通过 `validateCourseBlueprintV2`；新课程必须携带 CourseMission。
- 每章最后一个任务必须触发 Checkpoint；只有评估结果可投影为 Memory 掌握状态。
- 学习流顺序由 `sequence` 和数组位置共同约束，不能按随机时间排序。
- 章节状态机转换必须走 `state-machine.ts`。
- SSE 输出必须可解析、幂等且可恢复。
- Python `/api/*` 在配置 `PYTHON_INTERNAL_TOKEN` 后要求服务间令牌。
- 用户身份由 Next 代理转换为 `X-Account-Id`，Python 不直接读登录 cookie。
