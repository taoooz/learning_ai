# 课程质量提升计划：对齐 HyperKnow 流式学习体验

> 依据：docs/课程案例/Hyperknow 课程案例.html（竞品学习会话完整存档）
> 日期：2026-09-20
> 范围：课程内容质量（生成侧），不含 UI 视觉

## 1. 竞品案例拆解

案例是一节真实的 Agentic Learning 学习会话（意图建模/RAG 主题）。单任务内容的多模态打包：

| 内容元素 | 竞品用法 | 数量/密度 |
|---|---|---|
| **Mermaid 流程图** | 概念流动/转换逻辑可视化（如「用户语言→映射层→系统原语」） | 单课程 49 个 flowchart，mermaid 引用 156 次 |
| **Definition 定义卡** | 核心概念专用卡片（术语+英文对照+精确定义） | 每个核心概念一张 |
| **对比表格** | 多列结构化对比（「用户的话 \| 系统原语 \| 为什么这么拆」） | 单会话 37 个 table |
| **Example 例卡** | 双场景例子（查询报表场景 + 点餐类比场景） | 每概念 1-2 个 |
| **MEMORY 记忆卡** | 关键结论强调标记 | 每节 2-4 处 |
| **Key Points / Takeaways** | 要点收尾 | 每节 1 组 |
| **check-in 检查** | 段落结尾自然提问：「这个概念你是否清晰？你更倾向于看作 API 还是函数调用？」 | 每概念 1 次 |

### 教学法特征（比块类型更重要）

1. **类比分层降级**：先用专业类比（编译原理：自然语言=高级语言，原语=机器码）→ 用户说「没理解」→ **换生活类比完全重讲**（乐高积木/餐厅点餐）→ 表格逐行强化 → 确认理解才继续。智能体可见地调整策略（「沉思：Refining Explanation」「换类比重讲」）。
2. **多表征轰炸**：同一概念用定义/例子/表格/图/要点讲 5 遍，每个表征角度不同——不是重复，是编码多样性。
3. **结构化伪代码**：把模糊需求拆成原语清单（ADD_ITEM(炒饭)/REMOVE_INGREDIENT(葱)），让抽象概念可执行化。
4. **单元→任务层级**：Unit 1-3 → Task 1.1，任务编号带层级（我们 chapter→task 是平的，差距小）。
5. **进度鼓励**：「25%，做得不错！」（我们只有进度标头）。

## 2. 我们的现状（对照基线）

当前 task_content prompt（task-content-v2）全部约束：

> 300～500 字中文正文 + 口语化 + 结尾 > 引用块要点

**没有**：块类型要求、结构顺序、类比策略、可视化引导、定义卡、表格引导。实测走查（HTTP 缓存/Git/Flexbox 三门课）任务内容几乎全是单块 markdown 纯文字——因为 prompt 没要求多样，LLM 就选最省事的输出。

协议能力：4 种块（markdown/key_point/example/comparison）+ sources_ready（刚接线）。渲染层 TaskBlocksV2 仅覆盖这 4 种。**没有 diagram/可视化块**。

## 3. 差距排序（按质量影响）

| # | 差距 | 影响 | 实现成本 |
|---|---|---|---|
| 1 | **无内容配方**：块组合靠 LLM 自觉，实测退化成纯文字 | 高——直接决定内容形态丰富度 | 低（纯 prompt） |
| 2 | **无可视化块**：流程/架构主题纯文字，竞品用 49 个图 | 高——抽象概念理解成本 | 中（协议+渲染+prompt） |
| 3 | **无质量评测基线**：改了配方不知道是否变好 | 中——质量迭代的前提 | 低（脚本+rubric） |
| 4 | **无响应式重讲**：没懂时 tutor 只答不重组内容 | 中——补偿性教学闭环 | 中高（跨 tutor/内容生成） |
| 5 | 进度鼓励缺失 | 低（体验层） | 低 |

## 4. 改进计划（4 个切片，按序执行）

### 切片 1：内容配方（Content Recipe）——先做，ROI 最高

按 teachingPattern 定义显式块组合配方，写入 task_content prompt：

- **explain**：markdown 讲解（300-500字，含生活类比）→ key_point 定义卡（3-5 条要点，首条为精确定义）→ example 具体例子（≥100字）→ > takeaway
- **worked_example**：markdown 场景引入 → example 完整拆解（步骤化）→ key_point 模式总结 → takeaway
- **compare**：markdown 引入 → comparison 表（≥3 行×≥3 列）→ markdown 分析关键差异 → takeaway
- **process**：markdown → 有序步骤（markdown 有序列表，每步含做什么+为什么）→ key_point 易错点 → takeaway
- **practice**：markdown 场景 → example 示范 → markdown 引导实践 → takeaway

Prompt 硬约束：块序列必须齐全、每块最少内容量、块间不得重复同一句话。
验收：3 个主题 × 不同模式生成 → 自动检查块类型覆盖与内容量下限。

### 切片 2：内容质量评测基线

- 固定评测集：3 主题（流程类/对比类/概念类）× 对应模式
- Rubric 维度：块配方完整度 / 类比质量（生活化且准确）/ 例子具体度（有人物场景数字）/ 表格信息密度 / takeaway 概括力
- 评分方式：结构维度程序判分（块类型/字数），质量维度 LLM rubric（复用 checkpoint 回归模式）
- 产出：基线分数 → 切片 1 改动后复测对比

### 切片 3：diagram 块（Mermaid）

- 协议：新增 `diagram` 内容块（`{type:'diagram', language:'mermaid', source:string}`）
- 渲染：TaskBlocksV2 加 mermaid 渲染（npm mermaid 包），语法错误降级显示代码块
- prompt：process/derive/compare 模式引导生成流程图（「涉及流程/架构/状态转换时输出 diagram 块」）
- 降级链：LLM 输出非法 mermaid → 服务端校验（mermaid.parse）→ 失败转普通代码块 markdown
- 对标：竞品单课程 49 图——我们流程类内容从 0 到 1

### 切片 4：响应式重讲（与 P2 tutor 衔接）

- 触发：同一概念连续 2 次困惑信号（tutor 问答里出现「没理解/不清楚」）
- 动作：自动生成「替代讲解」补充块——换类比（专业类比→生活类比）、换表征（文字→表格），插入学习流（不覆盖已展示内容，符合红线）
- 已有基础：tutor 四意图的 switch_explanation/expand_current + engagement 困惑信号采集
- 竞品对标：用户「没理解」→ 沉思（可见策略调整）→ 乐高类比重讲 → 表格强化 → 确认

### 暂不做（记录理由）

- MEMORY 记忆卡：key_point 已覆盖语义，纯视觉变体，收益低
- 进度鼓励语：体验层微调，不解决质量问题
- 单元层级：chapter→task 已够用，多一层加导航复杂度

## 5. 执行顺序与验收

1 → 2（基线）→ 复测 1 → 3 → 4。总预计 3-4 个工作会话。
每切片完成：质量门全绿 + 评测集分数对比 + CHANGELOG。
