# 用户画像维护逻辑 v2

> 与 v1 的核心区别：**三层画像架构**（L1 长期 / L2 章节运行时 / L3 任务上下文）+ **取消章节末小测后的 mastery 重设计**（完全靠过程信号 + 多 task 一致性确认）+ **偏好系统支持下调**（修复 v1 "只升不降"）。

---

## 全局视角

```
显式填写 ─→ LLM 提取 7 维洞察 ──→ L1.stableFacts
                                        ↑
                                        │（章节末聚合）
                                        │
┌─ L3 任务上下文 ──┐                    │
│ task done       │ ──→ L2 ChapterRuntimeState ──→ L1.conceptProjections
│ 用户输入        │                                + L1.topicProjections
│ Director.action │                                + L1.preferences
│ 长停顿          │
└─────────────────┘
                ↓
        MemoryStoreV3（统一数据源）
                ↓
        ┌───────┼───────┐
        ↓       ↓       ↓
     Planning Director Recap
     Payload  Payload  Payload
```

三种 Payload 在不同场景驱动个性化：
- **Planning**（Outline / TOC / ChapterPlan v1 用）
- **Director**（章节内 Director Agent 用，v2 新增）
- **Recap**（章节末聚合用，v2 新增）

---

## 一、三层画像架构 ★

### L1 长期画像（保留 V3）

跨课程、跨章节的稳定状态。

| 数据 | 字段 | 更新策略 |
|------|------|---------|
| stableFacts | identity / goal / knowledge_background / analogy_experience | 显式填写或 LLM 提取，confidence 0.80–0.95 |
| conceptProjections | masteryScore / recentErrors / recentSuccesses / verificationSource[] | 行为事件触发 + Recap 聚合 |
| topicProjections | familiarityScore / lastActiveAt | 按 concept 平均聚合 |
| preferences | explanationStyles / paceSignal | Recap 时从 L2 emerging 晋升 |
| episodicMemory | 课程/聊天/章节摘要 | append-only，超限 LRU |

### L2 章节运行时（v2 新增）★

仅当前章节有效，章节完成后聚合写入 L1 并归档。

```ts
ChapterRuntimeState {
  chapterId
  startedAt
  objectiveProgress: Record<objectiveId, 'untouched'|'partial'|'covered'>
  taskHistory: {
    taskId
    goal
    conceptRefs[]
    durationMs
    userMessageCount         // 用户问了几次
    directorActions[]        // expand_here / insert_task / ... 触发过几次
    smoothlyCompleted: boolean   // 无任何 expand/insert 信号即推进 = true
  }[]
  currentDifficultyOffset: number    // -1..+1, 决定下一 task 起点
  emergingPreferences: {
    kind: 'examples_first' | 'step_by_step' | 'analogy' | 'comparison' | 'plain_language'
    evidence: string[]
    count: number              // 章节内出现次数（≥2 才晋升 L1）
  }[]
  confusionMarkers: {
    conceptId
    triggers: ('expand_here' | 'insert_task' | 'plain_text')[]
    count: number
  }[]
  paceSignal: 'fast' | 'normal' | 'slow'     // 基于 task 实际 vs 预估时长
  revisePlanCount: number                    // 触发过几次 revise_plan
  insertTaskCount: number                    // 触发过几次 insert_task
}
```

### L3 任务上下文（v2 新增，瞬态）

仅在单个 task 学习期间存在，不持久化。Director Agent 调用时拼装。

```ts
TaskContext {
  taskId
  taskStartedAt
  userMessagesInThisTask: string[]
  visualHintsRendered: string[]
  inlineAnswerCount: number
  longPauseTriggered: boolean
}
```

task done 时，L3 的关键信号聚合到 L2.taskHistory。

## 二、显式画像：从用户填写到结构化洞察（保留 v1）

完全沿用 v1 设计：

| 字段 | 内容 |
|------|------|
| name / targetJob / workExperience / education | 用户填写 |
| workSummary / educationSummary / analogyExperiences / learningStyle / technicalLevel / valuePriorities / summary | LLM 提取 7 维洞察 |

`syncProfileToV3()` 将洞察转化为 L1.stableFacts，confidence 0.80–0.95。

## 三、隐式画像：从学习行为到概念掌握度（v2 重设计）★

### 行为事件类型（v2 修订）

| 事件 | 触发时机 | 更新对象 |
|------|---------|---------|
| `task_started` | 用户进入 task | L3.taskStartedAt |
| `task_user_message` | 用户在输入框提交 | L3.userMessagesInThisTask |
| `director_action_taken` | Director 返回 action | L3 + L2 |
| `task_done_smooth` | 用户「下一步」无 expand/insert 信号 | L2.taskHistory（smoothlyCompleted=true）+ 概念弱信号 +0.18 |
| `task_done_with_signals` | 用户「下一步」但触发过 expand/insert | L2.taskHistory + 概念限制 ≤ 0.6 |
| `chapter_completed` | 最后 task done | Recap 触发 → L2 聚合到 L1 |
| `course_generated` / `chat_session_summarized` | 同 v1 | episodicProjection |

### Mastery 计算的新规则（重要）

由于取消了章节末小测，**强验证锚点消失**，必须重新设计 mastery 信号来源。

#### verificationSource 加权（v2 修订）

| 来源 | 单次权重 | 说明 |
|------|---------|------|
| `task_done_smooth`（无信号顺利推进） | 0.5 | 弱信号，但章节内多次累积可信 |
| `task_done_with_signals`（触发 expand/insert） | -0.2 | 负信号，限制 mastery ≤ 0.6 |
| `chat_explicit_understood`（用户主动说"懂了"） | 0.6 | 中等信号 |
| `director_proceed_after_question`（提问后明确表示懂） | 0.7 | 较强信号 |
| `chat_confusion`（用户表达没懂） | 限制 ≤ 0.4 | v1 保留 |
| `directors_expand_here` | -0.15 | 困惑信号 |
| `directors_insert_task` | 限制 ≤ 0.4 | 强困惑信号 |

#### 新 mastered 判定（双重保险）

```
mastered ⇔
  (1) weighted_score ≥ 0.78
  (2) 至少 2 个不同 task 中涉及该概念且 smoothlyCompleted
  (3) 章节内无 confusion 信号
```

比 v1 单纯"≥0.78 + 无近期错误"更严苛。意图：没有小测兜底，多 task 一致性是补偿。

#### 其他状态（保留 v1 阈值）

| 状态 | 条件 |
|------|------|
| fragile | weighted_score ≥ 0.6 |
| learning | weighted_score > 0 或有困惑信号 |
| unknown | weighted_score = 0 且无信号 |

### 主题熟悉度（保留 v1）

`familiarityScore = avg(concept.masteryScore)` 上限 0.95。

阈值：advanced ≥0.82 / intermediate ≥0.62 / beginner ≥0.38 / novice <0.38。

## 四、遗忘曲线（保留 v1）

- masteryScore 衰减：30 天半衰期
- freshness 衰减：21 天半衰期
- 答对复习间隔 7 天 / 答错 2 天（v2 中"答错"对应 task_done_with_signals 或 chat_confusion）
- 概念清理：衰减后 mastery < 0.3 且 90 天未更新 → 删除

## 五、偏好系统（v2 修订：支持下调）★

### 偏好检测规则（保留 v1 关键词表）

| 关键词 | 偏好 | 单次 confidence |
|--------|------|----------------|
| "一步一步""分步骤""逐步" | step_by_step | 0.74 |
| "举个例子""例如""比如" | examples_first | 0.72 |
| "类比""打比方" | analogy | 0.72 |
| "简单点""通俗点""白话" | plain_language | 0.68 |
| "区别""对比" | comparison | 0.70 |

### v2 新增：章节内 emerging → L1 晋升

偏好不再首次检测就直接写 L1，而是先记入 L2.emergingPreferences：

```
首次检测 → L2.emergingPreferences[kind].count = 1
重复 → count +1
章节末 Recap：
  if count ≥ 2 → 晋升到 L1.preferences（confidence = 0.72 + (count-1)*0.05）
  else → 丢弃，不污染 L1
```

### v2 新增：偏好下调机制（修复 v1 "只升不降"）

| 触发 | 动作 |
|------|------|
| 用户输入"换个方式讲"/"不要再 X" | L1.preferences[相关 kind].confidence -0.1 |
| 用户主动 revise_plan 移除某教学风格 | -0.15 |
| 连续 5 个 task 该偏好 kind 已应用但用户仍频繁提问 | -0.05 |
| confidence 跌破 0.5 | 从 L1.preferences 移除 |

### 偏好作用范围

L1.preferences 通过 Planning Payload 流入 ChapterPlan 生成 prompt。
L2.emergingPreferences 通过 Director Payload 流入 Director Agent 决策。

## 六、困惑信号检测（v2 简化）

### v1 关键词匹配 + v2 行为信号融合

| 来源 | 信号 |
|------|------|
| 用户输入含 "没懂""不懂""还是不明白""有点懵""看不懂""卡住了" 等 13 关键词 | confusion 弱信号 |
| Director.expand_here 触发 | confusion 中信号 |
| Director.insert_task 触发 | confusion 强信号 |
| 同章节同概念出现 ≥2 次任意 confusion 信号 | confusion 高置信度 |

### 对掌握度的影响

```
confidence = min(0.9, 0.55 + 重复次数 × 0.07)

mastery 限制：
  弱 confusion → ≤ 0.6
  中 confusion → ≤ 0.5
  强 confusion → ≤ 0.4
```

---

## 七、Recap 阶段的画像聚合（v2 新增）★

章节最后一个 task done 触发，是 L2 → L1 的唯一通道。

### 聚合规则

| L2 数据 | L1 落点 |
|---------|---------|
| taskHistory[smoothlyCompleted].conceptRefs | conceptProjections +0.18 each + verificationSource='task_done_smooth' |
| taskHistory[with_signals].conceptRefs | conceptProjections 限制 ≤0.6 + verificationSource='task_done_with_signals' |
| confusionMarkers | conceptProjections.recentErrors |
| emergingPreferences[count≥2] | preferences 晋升或 confidence 上调 |
| objectiveProgress | topicProjections.familiarityScore 重算 |
| paceSignal | preferences.pace |
| revisePlanCount / insertTaskCount | episodicProjection 记录 |

### LLM 精炼（保留 v1）

Recap 同时触发一次 LLM 精炼，产出：
- learningSummary（更新 L1.profile.summary）
- preferenceUpdates（confidence 取 max，但 v2 允许 -0.1）
- conceptCorrections（差异 > 0.15 才修正）

## 九、数据规模限制（v2 微调）

| 数据类型 | v1 上限 | v2 上限 | 变化原因 |
|---------|--------|--------|---------|
| 概念 | 200 | 200 | 不变 |
| 主题 | 50 | 50 | 不变 |
| 课程 | 30 | 30 | 不变 |
| 事件（热数据） | 180 | 240 | v2 增加 director_action 事件 |
| 事件（重要） | 40 | 60 | v2 增加 chapter_recap 事件 |
| 偏好 | 12 | 12 | 不变 |
| **L2 ChapterRuntimeState** | - | **每用户 5 个章节** | 完成的章节 LRU 归档为 episodic |

L2 不是无限留存：完成的章节聚合后只保留摘要进 episodic，原始 taskHistory 归档清理。

## 十一、关键设计思想与风险点（v2）

### v2 新增/修订设计思想

| 设计 | 策略 | 意图 |
|------|------|------|
| 三层画像 | L1 长期 / L2 章节 / L3 任务 | L2 缓冲避免单次状态污染长期画像 |
| 取消章末小测 | 多 task 一致性替代单次强验证 | 体验连贯 |
| 偏好 emerging 机制 | 章节内 ≥2 次才晋升 L1 | 减少偶然措辞被永久记录 |
| 偏好支持下调 | 用户表达"换个方式" → -0.1 | 修复 v1 "只升不降" |
| Mastery 多 task 一致性 | mastered 需 ≥2 个 task 涉及该概念且顺利 | 没有小测兜底的补偿机制 |
| 困惑信号融合 | 关键词 + Director.action 双源 | 减少误判 |
| L3 瞬态、L2 归档、L1 持久 | 数据生命周期分明 | 控制 localStorage 膨胀 |

### v1 保留的设计思想

答错权重 > 答对、节点完成 ≠ 掌握、显式 > 隐式、概念修正高门槛。

### v2 新风险点

| 风险 | 说明 |
|------|------|
| 取消小测后 mastery 准度下降 | 需要监控 mastered 概念在后续课程中的"被重新困惑率" |
| L2 状态丢失风险 | 用户中途关闭/换设备，L2 丢 → 章节进度重置。需要更频繁的 localStorage 写入 |
| Director.note_signal 过敏 | 误判一次情绪为偏好/困惑会持续影响。需要"单次不入 L1"的硬门槛 |
| 偏好下调可能矫枉过正 | -0.1 阈值待 A/B |
| L1↔L2 聚合时机集中在 Recap | 章节中途崩溃会丢失整章信号。可考虑每 N 个 task 增量预聚合 |

### v1 遗留风险（仍在）

阈值经验值无 A/B、概念别名表规模小、"换一批"按钮无效、跨设备同步缺失、前端测试不足。
