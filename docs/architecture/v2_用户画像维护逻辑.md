## 1. 目标与原则

本文定义 V2 如何记录用户起点、学习过程、理解证据、概念状态和补救效果，并将这些信息安全地用于后续教学。它不描述“模型觉得用户是什么样的人”，而是定义可追溯、可解释、可撤销的学习状态。

V2 的基本原则：

1. **证据优先**：掌握度必须主要来自与目标绑定的能力证据，不能由点击继续、阅读时长或停留时间直接推断。
2. **分层保存**：当前任务上下文、章节运行时、课程级学习状态和长期画像分开存储，避免短期噪声污染长期结论。
3. **事实与推断分离**：用户明确表达、系统观察到的行为、模型推断的候选信号必须分别标记。
4. **模型不直接写长期画像**：模型只返回候选信号或评估结果，由规则层决定是否写入、更新或降权。
5. **可追溯可修正**：每条证据保留来源、时间、目标、评估方式和版本；新证据追加，不静默改写历史。
6. **不伪造掌握**：证据不足时可以允许用户继续，但必须保留“未验证”或“脆弱”状态。
7. **低摩擦个性化**：画像应减少重复、调整解释方式和安排复习，而不是让用户反复填写问卷。
8. **最小必要信息**：只向模型注入完成当前教学动作所需的画像摘要，不发送无关的全量个人历史。

## 2. 学习状态的四个层次

```text
L0 当前交互上下文
  ↓
L1 章节运行时状态
  ↓
L2 课程学习状态
  ↓
L3 长期学习画像
```

### 2.1 L0：当前交互上下文

有效期通常为当前任务或当前答疑请求，保存：

- 当前任务目标和概念。
- 当前任务已经展示的内容摘要。
- 用户当前问题、反馈和请求的表达方式。
- 当前 Checkpoint 的题面、答案和待评估状态。
- 本次请求需要的最近几条 Stream Item。

L0 用于生成当前回答或教学动作，不直接形成长期结论。

### 2.2 L1：章节运行时状态

有效期为当前章节，保存：

- 当前 Chapter Plan 和版本。
- 已完成、跳过和待完成任务。
- 本章学习流及其顺序。
- 本章目标对应的证据。
- 当前任务状态、待处理请求和滚动锚点。
- 本章内出现的未解决问题、补救记录和调整记录。

L1 是章节恢复和章节完成判断的事实来源。

### 2.3 L2：课程学习状态

跨章节保存课程内相对稳定的状态：

- 用户在本课程各目标上的证据汇总。
- 已完成章节及其 Recap。
- 尚未验证或较脆弱的目标。
- 用户在本课程中已经明确掌握或排除的范围。
- 后续章节的前置风险。

L2 可用于生成后续 Chapter Plan，但不能覆盖用户当前章节已经展示的事实。

### 2.4 L3：长期学习画像

跨课程、跨主题保存，只有达到明确门槛才更新：

- 稳定的知识状态或技能状态。
- 用户长期偏好的解释形式、内容深度和节奏。
- 反复出现的概念混淆模式。
- 已验证有效的补救方式。
- 需要复习的主题和概念。
- 用户主动声明的目标、边界和学习约束。

长期画像不是人格画像，也不应保存与教学无关的敏感推断。

## 3. 信号与证据分级

### 3.1 三类信息

| 类别 | 示例 | 能否直接更新掌握度 |
|---|---|---|
| 参与信号 | 打开章节、阅读、停留、点击继续、退出位置 | 不能 |
| 自我报告 | “我会了”“太难了”“我想快一点” | 只能作为弱证据或偏好输入 |
| 能力证据 | 场景判断、自我解释、微实践、错误诊断、后续迁移 | 可以，经规则评估后更新 |

参与信号可用于体验优化和识别流失位置，但不得写入 `demonstrated` 掌握结论。

### 3.2 证据强度

```ts
type EvidenceStrength = 'weak' | 'moderate' | 'strong';

type EvidenceKind =
  | 'exposure'
  | 'self_report'
  | 'scenario_choice'
  | 'self_explanation'
  | 'sequence'
  | 'micro_practice'
  | 'error_diagnosis'
  | 'transfer_task';
```

默认强度建议：

- `exposure`：weak。
- `self_report`：weak。
- `scenario_choice`、`sequence`：moderate；题目质量和迁移程度不足时可降级。
- `self_explanation`、`micro_practice`、`error_diagnosis`：moderate 到 strong，取决于 Rubric 和答案质量。
- `transfer_task`：strong，但必须明确绑定课程目标和新情境。

证据强度不是固定真理。每条证据还必须记录评估置信度、题目难度、是否补救后取得以及是否存在提示。

### 3.3 不同结果的含义

```ts
type EvidenceOutcome =
  | 'demonstrated'
  | 'partial'
  | 'not_demonstrated'
  | 'skipped'
  | 'invalidated';
```

- `demonstrated`：在指定情境和 Rubric 下达到要求，不等于永久掌握。
- `partial`：理解了部分关键点，存在可定位缺口。
- `not_demonstrated`：本次没有取得足够证据，不等于用户完全不会。
- `skipped`：用户未作答或选择稍后，不得当作失败或掌握。
- `invalidated`：题目、版本或评估过程存在问题，不能参与掌握度聚合。

## 4. 核心数据结构

### 4.1 学习证据

```ts
interface LearningEvidence {
  evidenceId: string;
  protocolVersion: 2;
  courseId: string;
  chapterId: string;
  objectiveId: string;
  conceptKeys: string[];
  taskId?: string;
  checkpointId?: string;
  kind: EvidenceKind;
  outcome: EvidenceOutcome;
  strength: EvidenceStrength;
  score?: number;
  confidence: number;
  answerSummary?: string;
  misconceptionCodes: string[];
  hintLevel: 'none' | 'light' | 'substantial';
  isRemediationAttempt: boolean;
  sourceItemId: string;
  planVersion: number;
  createdAt: number;
  evaluator: 'rule' | 'model' | 'hybrid';
  evaluationVersion: string;
}
```

`answerSummary` 只能保存必要的可审计摘要。除非产品有明确的隐私和保留策略，不应把用户开放答案无限期复制到长期画像。

### 4.2 概念状态

```ts
type ConceptStatus =
  | 'unknown'
  | 'introduced'
  | 'developing'
  | 'demonstrated'
  | 'fragile'
  | 'needs_review'
  | 'not_applicable';

interface ConceptLearningState {
  conceptKey: string;
  status: ConceptStatus;
  evidenceCount: number;
  strongEvidenceCount: number;
  recentEvidenceIds: string[];
  misconceptionCodes: string[];
  effectiveRemediationPatterns: string[];
  lastDemonstratedAt?: number;
  lastAssessedAt?: number;
  confidence: number;
  updatedAt: number;
}
```

状态含义：

- `unknown`：没有足够接触或证据。
- `introduced`：内容已出现，但尚无能力证据。
- `developing`：存在部分证据或正在形成理解。
- `demonstrated`：近期在目标情境中达到要求。
- `fragile`：曾经证明，但证据少、已久未验证或后续表现不稳定。
- `needs_review`：出现明确缺口、错误模式或多次未证明。
- `not_applicable`：被课程边界或用户目标排除，不应安排为必学内容。

### 4.3 用户偏好

```ts
type PreferenceSource = 'explicit' | 'repeated_behavior' | 'model_candidate';

interface LearningPreference {
  preferenceKey:
    | 'explanation_style'
    | 'content_depth'
    | 'pace'
    | 'example_domain'
    | 'practice_frequency';
  value: string;
  confidence: number;
  source: PreferenceSource;
  supportingSignalIds: string[];
  firstObservedAt: number;
  lastObservedAt: number;
  status: 'candidate' | 'active' | 'superseded';
}
```

用户明确说“以后多举例”可以快速成为候选偏好；只有重复表达或后续行为支持时，才提升为稳定偏好。单次“这次我想快点”不应永久改变节奏。

### 4.4 长期画像

```ts
interface LearnerProfileV2 {
  profileVersion: 2;
  userId: string;
  conceptStates: Record<string, ConceptLearningState>;
  preferences: LearningPreference[];
  activeGoals: string[];
  reviewQueue: ReviewItem[];
  evidenceSummary: ProfileEvidenceSummary;
  updatedAt: number;
}

interface ReviewItem {
  conceptKey: string;
  reason: 'fragile' | 'needs_review' | 'stale_evidence' | 'user_requested';
  priority: 'low' | 'medium' | 'high';
  sourceCourseId?: string;
  createdAt: number;
  dueAt?: number;
}

interface ProfileEvidenceSummary {
  totalEvidence: number;
  demonstratedObjectives: number;
  fragileConcepts: number;
  unresolvedMisconceptions: number;
  lastAggregatedAt?: number;
}
```

## 5. 画像更新规则

### 5.1 参与信号规则

参与信号可以记录为分析事件，例如：

```ts
interface EngagementSignal {
  signalId: string;
  userId?: string;
  courseId: string;
  chapterId: string;
  taskId?: string;
  kind:
    | 'chapter_opened'
    | 'content_viewed'
    | 'continued'
    | 'paused'
    | 'exited'
    | 'returned';
  value?: number;
  createdAt: number;
}
```

它们可以支持：

- 首屏和任务体验分析。
- 识别用户在哪个任务退出。
- 调整默认内容长度和加载体验。
- 判断预取是否有价值。

它们不能单独支持：

- 将概念标为 `demonstrated`。
- 将用户加入“已掌握”集合。
- 直接压缩后续必需教学内容。
- 直接更新长期能力等级。

### 5.2 自我报告规则

自我报告分为能力声明和体验/偏好声明：

```ts
type SelfReportKind =
  | 'confidence'
  | 'difficulty'
  | 'ready_to_continue'
  | 'wants_more_detail'
  | 'wants_example'
  | 'wants_different_explanation'
  | 'prior_knowledge'
  | 'goal_change';
```

规则：

- `ready_to_continue` 只控制推进，不增加 mastery。
- `wants_more_detail`、`wants_example` 和 `wants_different_explanation` 作为当前任务教学动作输入。
- `prior_knowledge` 可以影响计划建议，但不能跳过高风险前置目标而不验证。
- `confidence` 可作为弱信号，与能力证据冲突时以能力证据为准。
- `goal_change` 需要更新课程目标契约或重新确认范围，不能仅修改画像字段。

### 5.3 能力证据规则

规则层根据以下维度聚合：

1. 目标和概念是否明确绑定。
2. 证据类型和 Rubric 是否适合该目标。
3. 答案是否独立完成，提示程度如何。
4. 评估置信度是否达到阈值。
5. 是否为补救后尝试。
6. 后续或迁移任务是否支持或反驳原结论。
7. 证据是否已过旧。

建议的初始规则：

- 单条 `weak` 证据不得把概念标为 `demonstrated`。
- 一条高置信度 `strong` 证据可以将 `developing` 提升为 `demonstrated`，但仍保留复核时间。
- `partial` 进入 `developing` 或 `fragile`，并保留 `misconceptionCodes`。
- 连续两次对等目标 `not_demonstrated`，进入 `needs_review`，触发 P3 补救策略。
- 补救后首次通过可标为 `developing` 或 `demonstrated`，但必须记录 `isRemediationAttempt: true`。
- 后续迁移失败可以将 `demonstrated` 降为 `fragile`，不能删除原始成功证据。

初始阈值应通过样本回归校准，不能把以下示例数字当作永久产品真理：

```ts
interface EvidenceAggregationPolicy {
  minConfidenceForAggregation: number;
  strongEvidenceThreshold: number;
  staleAfterDays: number;
  maxRemediationRounds: 2;
}
```

## 6. 补救效果记录

补救的目标不是让用户“答对一次”，而是判断哪种教学变化真正改善了理解。

```ts
interface RemediationRecord {
  remediationId: string;
  courseId: string;
  chapterId: string;
  objectiveId: string;
  conceptKeys: string[];
  triggerEvidenceId: string;
  misconceptionCodes: string[];
  strategy:
    | 'concrete_example'
    | 'counterexample'
    | 'simpler_explanation'
    | 'different_analogy'
    | 'step_by_step'
    | 'prerequisite_review'
    | 'guided_practice';
  beforeEvidenceId?: string;
  afterEvidenceId?: string;
  outcome: 'helped' | 'partially_helped' | 'not_helped' | 'abandoned';
  round: number;
  createdAt: number;
}
```

### 补救选择原则

- 同一误解不重复使用完全相同的讲法。
- `LOCAL_MISCONCEPTION` 优先原地短补救。
- `PREREQUISITE_GAP` 才考虑插入前置任务。
- 连续最多两轮；达到上限后标记待复习并允许继续。
- 补救成功不删除失败记录，而是形成“前后证据对”。
- 某种补救方式对同一用户多次有效时，可以作为候选偏好或后续教学排序输入，但不应无条件套用。

## 7. 证据聚合与画像投影

### 7.1 聚合时机

- **P0**：只定义结构和持久化边界，不改变掌握度。
- **P1**：记录任务完成和参与信号，但不生成 mastery 证据。
- **P2**：记录问题、回答和候选困惑/偏好信号，不直接更新长期画像。
- **P3**：启用 Checkpoint 证据、补救记录和章节级聚合。
- **P4**：允许证据驱动本章剩余任务调度，但仍不能改写已展示内容。
- **P5**：启用跨课程画像、复习队列、多设备同步和质量治理。

### 7.2 章节聚合

章节完成时执行：

```text
读取本章有效 LearningEvidence
  ↓
按 objectiveId / conceptKey 分组
  ↓
排除 invalidated，保留 skipped 为未验证
  ↓
应用 EvidenceAggregationPolicy
  ↓
生成 ChapterEvidenceSummary
  ↓
更新本章概念状态和 Recap
  ↓
P3+ 投影到课程状态；P5 再投影到长期画像
```

```ts
interface ChapterEvidenceSummary {
  chapterId: string;
  objectiveStates: Array<{
    objectiveId: string;
    status: 'introduced' | 'developing' | 'demonstrated' | 'fragile' | 'needs_review';
    evidenceIds: string[];
    unresolvedMisconceptions: string[];
  }>;
  demonstratedConcepts: string[];
  fragileConcepts: string[];
  reviewConcepts: string[];
  skippedEvidence: string[];
  aggregatedAt: number;
}
```

### 7.3 投影原则

- 原始证据是事实层，概念状态和画像是可重建的投影层。
- 投影更新失败时不能删除原始证据。
- 画像投影必须带 `updatedAt`、来源证据 ID 和规则版本。
- 规则升级后允许离线重算投影，不修改历史证据。
- 用户删除课程或学习记录时，按数据保留策略删除或匿名化相关证据。

## 8. 证据衰减与复习

“曾经证明”不等于“永远掌握”。V2 使用衰减标记提醒复核，但不自动抹除历史。

### 8.1 衰减条件

概念可因以下情况进入 `fragile` 或复习队列：

- 距最近有效证据超过策略规定时间。
- 仅有一条早期证据，缺少重复或迁移验证。
- 后续相关任务出现反复错误。
- 补救后通过但尚未在新情境中迁移。
- 用户主动表示不确定或请求复习。

### 8.2 复习队列规则

- 高风险前置概念优先级高于一般概念。
- 复习建议应在用户进入相关课程或章节时出现，不以打断当前学习为默认行为。
- 复习任务应优先采用短场景、微实践或错误诊断，而不是重新播放整章。
- 用户可以稍后复习；延期不会伪造为已完成。
- 复习产生的新证据与原课程证据分开记录，但可以共同更新概念投影。

## 9. 模型与规则层的边界

### 9.1 模型可以做什么

- 从用户问题识别候选困惑类型。
- 对开放式答案按 Rubric 给出结构化评估。
- 提取 `misconceptionCodes`、候选偏好和候选学习信号。
- 建议补救方式。
- 生成与目标绑定的 Checkpoint、反馈和 Recap。

### 9.2 模型不能直接做什么

- 直接写入 `LearnerProfileV2`。
- 直接把概念改为 `demonstrated`。
- 直接删除或覆盖历史证据。
- 直接跳过课程必需目标。
- 直接修改已展示 Learning Stream。
- 直接绕过版本、幂等和权限校验。

### 9.3 模型输出契约

```ts
interface CandidateLearningSignal {
  signalId: string;
  kind:
    | 'possible_misconception'
    | 'possible_preference'
    | 'possible_prior_knowledge'
    | 'possible_goal_change';
  conceptKeys?: string[];
  value: string;
  confidence: number;
  sourceItemId: string;
}

interface EvidenceEvaluationOutput {
  outcome: EvidenceOutcome;
  confidence: number;
  score?: number;
  misconceptionCodes: string[];
  feedback: string;
  candidateSignals: CandidateLearningSignal[];
}
```

所有模型输出都要经过 Schema 校验、业务边界校验和版本校验。低置信度输出可以记录为候选信号，但不能触发高影响的长期状态变化。

## 10. 隐私、透明度与数据治理

- 学习证据只收集完成教学和质量分析所需的最小字段。
- 长期画像不保存与学习无关的敏感属性推断。
- 开放答案摘要应避免复制不必要的个人信息。
- 日志记录 `reasonCode`、规则版本、来源 ID 和结果，不记录模型隐藏思维过程。
- 用户可以看到“哪里已验证、哪里建议复习”的解释性结果。
- “未验证”不能用羞辱性或确定性失败文案呈现。
- 删除或重置学习数据时，同时清理相应的画像投影和复习队列引用。
- 调试日志、原始答案和长期画像应采用不同保留周期。
- 生产环境不得将 API 密钥、完整鉴权信息或内部堆栈写入学习证据和用户可见内容。

## 11. 测试与质量标准

### 11.1 单元测试

- 参与信号不会更新 mastery。
- `ready_to_continue` 不会生成 demonstrated 证据。
- 不同证据强度的聚合结果符合策略。
- `skipped`、`invalidated` 不会被错误计入掌握。
- 补救最多连续两轮。
- 历史成功证据不会因后续失败被删除。
- 衰减只改变投影状态，不改变原始证据。
- 模型候选信号不能绕过规则层写入画像。

### 11.2 集成测试

- Checkpoint 提交、评估、重试和刷新恢复。
- 答错 → 补救 → 等价新题 → 证据聚合完整闭环。
- 章节完成时目标覆盖和证据状态正确。
- 旧 V1 课程不会误读 V2 画像字段。
- 画像更新失败时，章节证据仍然可恢复。
- 规则版本升级后可以重建投影而不重复创建原始证据。

### 11.3 质量指标

- 核心目标证据覆盖率。
- Checkpoint 首次通过率。
- 补救后通过率。
- 补救后再次困惑率。
- 被标记 demonstrated 后的迁移表现。
- 未验证目标的复习完成率。
- 错误画像更新率和用户纠正率。
- 模型评估与人工抽检的一致性。

## 12. 分阶段开发清单

## P0：建立证据边界

1. 定义参与信号、自我报告和能力证据的**分级边界和存储归属**；证据、概念状态和画像的详细类型字段推迟到 P3 开工前定稿（与课程生成逻辑 P0 范围一致，避免提前锁定后返工）。
2. 增加 `protocolVersion`、来源 ID、规则版本和时间字段的命名约定。
3. 实现序列化、校验和兼容读取。
4. 不改变现有 V1 mastery 行为。

**完成定义**：V2 能区分三类信号，能保存未验证状态，不能因点击继续直接增加 mastery。

## P1：记录章节事实

1. 记录任务完成、跳过和学习流事件。
2. 记录章节级参与信号。
3. 生成章节 Recap 所需的事实摘要。
4. 不将参与行为投影为能力证据。

**完成定义**：章节可恢复，学习经历可审计，但 P1 不宣称用户已经掌握目标。

## P2：记录答疑信号

1. 保存问题、回答和请求动作。
2. 提取候选困惑、偏好和先验知识信号。
3. 对候选信号设置置信度和来源。
4. 不自动写入长期画像，不自动改变 mastery。

**完成定义**：答疑成为学习轨迹的一部分，画像仍由后续规则或证据驱动。

## P3：启用证据与补救

1. 定稿并实现 Checkpoint 定义、提交和评估结果类型。
2. **结构化优先**：先启用程序判分的 `scenario_choice`、`sequence` 证据；开放式类型（`self_explanation`、`micro_practice`、`error_diagnosis`）在模型评估通过回归样本验证前不产生证据。
3. 实现证据账本和章节聚合。
4. 实现概念状态转换和补救记录。
5. 实现补救后再验证。
6. 将章节摘要投影到课程状态和复习入口。

**完成定义**：核心目标有可追溯证据；补救前后可比较；证据不足不会被标记为掌握；未验证的评估路径不产生证据。

## P4：证据驱动的局部调度

1. 将概念状态和误解编码提供给本章调度器。
2. 为压缩、加深、插入和重排设置阈值与次数上限。
3. 仅允许影响未展示任务。
4. 记录调度依据、置信度、结果和用户可见说明。

**完成定义**：调度可解释、可回退，不会因低置信度信号大幅改变路线。

## P5：长期画像正式化

1. 建立用户级服务端画像存储和投影重建。
2. 支持多课程、多设备和数据删除。
3. 建立证据衰减、复习队列和跨课程迁移评估。
4. 建立人工抽检、规则回归和画像质量监控。
5. 完成数据保留、匿名化和成本治理。

## 14. 明确禁止的实现捷径

- 用阅读时长、停留时间或点击继续直接增加 mastery。
- 把“我会了”当作唯一掌握证据。
- 让模型直接修改长期画像或概念状态。
- 用一次答对永久标记掌握。
- 答错后只展示正确答案而不重新验证。
- 用同一种补救讲法无限重试。
- 删除失败证据，只保留最后一次成功结果。
- 让低置信度候选信号触发高影响的课程重排。
- 把与学习无关的个人信息写入长期画像。
- 将归档文档中的旧阈值、字段或画像层级视为当前要求。
