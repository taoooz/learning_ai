# 开源方案调研：课程内容丰富度（2024-2026）

> 日期：2026-09-20
> 目的：为「课程内容形态升级」寻找可借鉴/可复用的开源方案
> 检索范围：GitHub（近两年活跃项目，star 优先）

## 0. 结论先行

**我们的架构方向是对的**（内容块类型 + 模型流式输出 JSON + 客户端映射渲染）——这是当前开源界主流做法，`vercel-labs/json-render`(16.9k★)、`thesysdev/openui`(9.8k★)、`tambo`(11k★) 都是这个模式。

**但块类型集严重贫瘠**：我们 4 种（markdown / key_point / example / comparison），且只有单列流式布局。

对比参照：
| 系统 | 内容单元 | 布局能力 | 交互能力 |
|---|---|---|---|
| 我们 | 4 种块 | 单列 | 无（读为主） |
| Mathigon | 叙事容器 + 多列 + 拖拽连线 + 图形 + 交互组件 + 测验 | 多列/嵌入式 | 拖拽/点击/滑动 |
| OpenHyperKnow（竞品克隆） | markdown + KaTeX + Q/A reveal + MCQ + 手写便签 + mermaid + 点阵画布 | 白板画布 | 打断提问 |
| json-render | 预定义组件 + 动作 | 全（含视频/PDF/3D） | 组件级交互 |

## 1. 竞品开源克隆（直接参照）

### OpenHyperKnow — `junjiezhou1122/OpenHyperKnow`
「a faithful clone of Hyperknow，基于 pi AgentSession SDK 而非 LangChain」

架构要点（可直接借鉴）：
- **4 个自定义工具**代替框架图：`search_web`（并行 DuckDuckGo 研究）/ `ask_user_questions`（**interrupt：park 一个 promise，浏览器经 WS 回答后 resolve**）/ `emit_course_outline`（流式蓝图）/ `emit_unit`（**逐单元渐进渲染**）
- **白板**：Kalam 手写字体 + 奶油纸质感 + 点阵网格画布；手写便签卡 + mermaid 图；多页导航；**每个元素带 `step_id`**（Hyperknow 的同步协议——讲解与元素落位的同步锚点）
- **中断式教学**：agent 讲到一半停下提问 → 学生回答 → agent 确认后从该点继续（不是 Q&A 弹窗，是教学流内嵌）
- 课程阅读器 markdown + KaTeX；练习为 Q/A reveal cards；测评单元 MCQ 即时评分（Mastered/Proficient/Review）

**对我们的启示**：`ask_user_questions` 的 interrupt 语义 + `step_id` 同步，是白板课/流式课「讲到哪里问哪里」的工程实现范式。

## 2. Generative UI 框架（解决「块类型 + 渲染」）

### `vercel-labs/json-render`（16.9k★，Apache-2.0，Vercel Labs）
「The Generative UI framework. Generate dynamic UIs from prompts **without sacrificing reliability**. **Predefined components and actions** for safe, predictable output.」

跨渲染目标（同一份 JSON 协议）：
React / React Native / **Remotion 视频** / **React-PDF** / HTML 邮件 / Vue / Svelte / SolidJS / 终端 Ink / Next.js 全栈 / **3D 场景**

**核心思想是「受限组件集 + 模型只做组合编排」**——模型不能发明任意 UI，只能在预定义组件+动作里选。这正是我们块协议该走的路（可控、可校验、安全）。

### `thesysdev/openui`（9.8k★，MIT）
「The Open Standard for Generative UI」，**renderer-agnostic + streaming-first**，自有中间语言 **比 JSON 省 67% token**，官方 React 支持 + 组件库 + 现成 chat 界面。

### 其他
- `CopilotKit/CopilotKit`（37k★）：Agent + Generative UI 前端栈
- `tambo-ai/tambo`（11k★）：React Generative UI SDK
- `vercel-labs/gemini-chatbot`（1.3k★）：AI SDK + generative UI 示例

**对我们的启示**：中间语言（非裸 JSON）可省 2/3 token——我们的 SSE delta 全是 JSON，长内容 token 成本可优化。组件集应当「预定义 + 可校验」，而非让模型自由发挥（我们已有此雏形，需扩充组件集）。

## 3. 交互式教材标杆（内容形态的黄金标准）

### `mathigon/textbooks`（391★）—— 获奖交互式数学教材
**内容语法设计**（Pug/自定义 DSL，比 markdown 表达力强很多）：

```
# Functions                    ← 章节
> section: relations           ← 元数据
> level: Intermediate
> next: sequences

::: column.grow                ← 多列布局容器
  叙事正文…
::: column(width=300)          ← 并排嵌入式（图/交互组件）
    x-relation
      .item(slot="domain") **Current User**    ← 拖拽连线交互题
      .item(slot="range") Lionpaw
```

**两个关键手法**：
1. **交互式组件作为一等内容块**（`x-relation` 拖拽连线、函数图像交互等）——学生**动手**而非只读
2. **叙事化包装**：用「哈利波特分院帽」故事讲「函数=每个输入映射唯一输出」——故事情境 + 类比 + 交互三者叠加
3. **多列布局**：正文与交互/图形并排，不是单列流

### `openai/interactive-textbook-demo`（58★，OpenAI 官方）
面向视障/语言与学习障碍人群的交互式教材（无障碍视角）。

### `ryoiki-tokuiten/Generative-Recursive-Education`（44★）

## 5. 内容地基：证据 grounding 与教育学

### `iamvetruvian/CourseForge2`（47★）—— 反向思路值得警惕
「**CourseForge does not generate synthetic content.** 」它搜索真实世界优质资源（YouTube 教程/文档/论文/Wikipedia/大学大纲）→ 提取概念结构 → 构建**课程 DAG（依赖感知）** → 向量相似度给每个节点分配最佳资源。

三条设计原则：
1. **Ground everything in discovered evidence** — 模型不得仅凭参数知识发明结构，每个概念须能追溯到发现阶段找到的真实内容；概念按「多少种独立来源确认」赋置信度
2. **Separation of concerns across models** — 不同 pipeline 阶段路由不同模型（分类要快、概念抽取要推理、骨架生成要创造性）
3. **Preserve context across stateless calls** — 维护并在每次调用注入「运行上下文」（骨架设计推理/节点设计注记/资源分配日志），让模型能作为自己先前决策的一致审查者

**对我们的启示**：我们刚接了搜索证据包（单任务级），CourseForge 把「证据 grounding」提升到**课程结构级** + **跨调用上下文一致性**——这是防止「模型幻觉出课程结构」的系统性方案。

### `GarethManning/education-agent-skills`（786★，CC BY-SA 4.0）
**165 个循证教育学技能，20 个领域**，面向教师/课程设计者/EdTech 构建者。领域含：
`explicit-instruction`（显性教学）、`memory-learning-science`（记忆科学）、`questioning-discussion`（提问与讨论）、`self-regulated-learning`（自我调节学习）、`inclusive-design`、`curriculum-assessment`、`ai-learning-science`、`systems-thinking` 等。
Domain 20 是首个**学生面向**领域：塑造 AI 在学习会话中如何回应的实时交互模式。

**对我们的启示**：内容配方（质量计划切片 1）不应凭直觉写，应以其循证教学技能为依据（如显性教学的结构、记忆科学的间隔/提取练习）。

## 7. 风险提示

- **不要照搬 Generative UI 的「自由生成任意 UI」**：json-render 明确强调「predefined components and actions for safe, predictable output」——自由生成 UI 会带来渲染崩溃、样式崩坏、token 爆炸。我们应扩组件集而非放开自由度。
- **CourseForge2 的「不生成合成内容」是另一种极端**：完全依赖外部资源会丧失个性化适配。合理位置是「结构 grounded + 表达生成」（我们当前搜索证据包的方向）。
- **Mathigon 的交互组件是人工设计的**（每个 x-relation 都有人写题目）——LLM 生成交互式组件的质量需要单独验证（参照我们 P3b 开放式题型做回归验证的方法）。
