# AI Learning 项目综述

## 产品定位

**Duolingo for Anything** — 用户输入任何感兴趣的主题，AI 自动生成专属学习路径，包含知识卡片、测验题目和聊天辅导。

核心差异点：**记忆驱动的渐进个性化**。不是一次性生成课程，而是随着用户学习不断调整——已掌握的跳过、薄弱的多练、困惑的补救，每轮课程都比上一轮更精准。

面向中文用户，全中文界面。

---

## 学习体验设计

### 用户旅程

```
首次进入 → 邀请码登录 → 填写个人信息（目标岗位/工作/教育）
    ↓
首页 → 输入想学的主题 / 选择系统推荐课程
    ↓
AI 澄清需求（最多3个单选题）→ 生成课程蓝图 → 生成章节目录
    ↓
进入课程 → 按章节学习：知识卡片 → 练习题 → 聊天辅导
    ↓
完成章节 → 解锁下一章节 → 画布记忆更新 → 下次课程更精准
```

### 学习步骤流（每个章节）

```
intro（章节标题 + 目标）
  → card1 → card2 → ... → card5-8
  → question1 → question2 → ... → question3-5
  → 完成 → 解锁下一章节
```

### 游戏化机制

| 机制 | 实现 |
|------|------|
| 节点解锁 | locked → available → completed，完成当前自动解锁下一 |
| 连续学习天数 | streak 记录，追踪当前和最佳纪录 |
| 进度可视化 | 顶部进度条 + 百分比 + 脉冲动画 |
| 完成庆祝 | 彩纸动画 + 弹窗 + 推荐下一个课程 |
| 答题反馈 | 正确弹跳 / 错误抖动动画 |
| 新手引导 | 预置系统课程（AI 课 / 理财课） |

## 课程生成策略

### 三阶段生成

| 阶段 | 目标 | 核心决策 |
|------|------|---------|
| **Outline** | 决定课程定位 | 提问还是直接生成？课程方向和重点是什么？用户水平如何定位？ |
| **TOC** | 决定内容组织 | 选哪种课程框架？每个章节选哪种教学策略？章节如何衔接？ |
| **Cards + Questions** | 生成教学内容 | 卡片深度随水平调整？可视化是否必要？题型和难度如何分配？ |

### 8 种课程框架

| 框架 | 适合场景 |
|------|---------|
| 渐进深入 | 完整入门路径，初学者优先选 |
| 问题驱动 | 用户有明确痛点 |
| 系统拆解 | 复杂领域，模块相对独立 |
| 对比辨析 | 选型决策 |
| 演进历程 | 技术演进史、行业变革 |
| 案例驱动 | 实战型学习 |
| 理论实践 | 技能型学习，需动手 |
| 项目实战 | 综合实战 |

### 8 种教学策略（每个章节独立选择）

| 策略 | 教学意图 |
|------|---------|
| 是什么-为什么-怎么做 | 概念入门 |
| 总-分-总 | 信息密集型，建结构 |
| 步骤拆解 | 操作流程，照着做 |
| 案例复盘 | 从具体到抽象 |
| 问题-方案 | 导向明确地解决问题 |
| 对比分析 | 帮助做选择和判断 |
| 时间线演进 | 建立历史纵深感 |
| 探索-推导 | 引导自主思考 |

### 个性化调节维度

| 维度 | 来源 | 影响 |
|------|------|------|
| 用户水平 | 记忆系统 estimatedLevel | 零基础→搭基础 / 有基础→聚焦实战 / 成熟→进阶决策 |
| 技术接受度 | 画像 technicalLevel | 术语密度：入门避术语 / 业务用常见术语 / 专家自由用 |
| 学习风格 | 画像 learningStyle | 理论型先讲为什么 / 实践型先讲怎么做 |
| 价值关注点 | 画像 valuePriorities | 内容侧重 |
| 可跳过知识 | 记忆系统 skippableBasics | 已掌握的不单独成章 |
| 必须覆盖概念 | 记忆系统 mustCoverConcepts | 薄弱点保证覆盖 |
| 风险概念 | 记忆系统 riskConcepts | 易混淆点重点辨析 |
| 可用类比 | 记忆系统 transferableBackground | 用用户熟悉场景举例 |
| 解释偏好 | 记忆系统 preferredExplanationStyles | 分步/例子/类比/通俗/对比 |

## 用户画像策略

### 双源画像

| 来源 | 内容 | 特点 |
|------|------|------|
| **显式画像** | 目标岗位、工作经历、教育背景 → LLM 提取 7 维洞察 | 起点高但更新慢 |
| **隐式画像** | 答题对错、聊天偏好、困惑表达、节点完成 | 持续积累，精度递增 |

### 概念掌握度模型

| 状态 | 条件 | 业务含义 |
|------|------|---------|
| mastered | ≥ 0.78 且无近期错误 | 可跳过 |
| fragile | ≥ 0.6 | 需巩固 |
| learning | > 0 或有错误 | 正在学 |
| unknown | = 0 且无错误 | 未接触 |

**关键设计**：答错影响（-0.22）大于答对（+0.18），节点完成只升到 0.62（fragile），需要答题验证才算 mastered。

### 遗忘曲线

30 天半衰期（实用折中，比纯艾宾浩斯更友好），配合 7 天/2 天复习间隔。

### 偏好检测

从聊天文本自动识别解释风格偏好（分步拆解/例子驱动/类比解释/通俗解释/对比讲解），多次出现才确认（5-6 次到高置信度），但当前设计存在"只升不降"的风险。

## 聊天辅导策略

学习页内嵌 AI 助手，两种快捷入口："深入理解"和"为什么错了"。

聊天携带 Chat Memory Payload，AI 知道用户当前在学什么概念、哪些掌握薄弱、最近问过什么，实现上下文感知。

聊天同时作为画像信号的采集渠道：偏好检测、困惑检测、掌握信号检测。

## 当前架构特点

### 优势

| 特点 | 价值 |
|------|------|
| 记忆驱动的渐进个性化 | 学得越多课程越精准 |
| 三种 Payload 粒度递进 | Planning 粗规划 → Teaching 细教学 → Chat 即时辅导 |
| 答错敏感设计 | 防止虚假掌握导致跳过关键内容 |
| Agent 搜索增强 | 生成内容可获取最新信息 |
| 可视化克制原则 | 有帮助才加，避免信息噪音 |
| SSE 流式体验 | 用户实时看到 AI 生成过程 |

### 已知风险

| 风险 | 影响 |
|------|------|
| 阈值均为经验值，无 A/B 测试 | 掌握度/遗忘曲线/偏好置信度的参数无法验证最优性 |
| 偏好只升不降 | 早期误检的偏好无法消除 |
| 概念修正门槛可能过高 | 小但重要的掌握度修正会被忽略 |
| 别名表规模极小 | 跨课程概念匹配大部分靠字符串相似度，精度有限 |
| "换一批"推荐按钮无效 | 代码逻辑阻止了二次生成 |
| 数据主要在 localStorage | 换设备即丢失，无跨端同步 |
| 前端缺少测试 | 关键业务逻辑（记忆聚合、进度追踪）缺少回归保障 |
