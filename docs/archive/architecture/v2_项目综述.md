# AI Learning v2 项目综述

> 与 v1 的核心区别：章节内由"卡片+题目的固定线性流"演化为"渐进式任务序列 + 用户随时提问"。学习节奏由用户主导，AI 在背后用 Director Agent 动态调整后续任务。

---

## 一、产品定位（保留）

**Duolingo for Anything** — 用户输入任何感兴趣的主题，AI 自动生成专属学习路径，包含渐进的教学任务、即时辅导、记忆驱动的个性化。

核心差异点不变：**记忆驱动的渐进个性化**。新增一层：**章节内的动态适配**——同一章节，不同用户、不同时间，看到的内容序列可以不同。

---

## 二、学习体验设计（v2 变化）

### 用户旅程

```
首次进入 → 邀请码登录 → 填写个人信息
    ↓
首页 → 输入主题 / 选系统课
    ↓
Outline（最多3问澄清）→ Blueprint → TOC（每章带学习目标）
    ↓
进入章节
    ↓
ChapterPlan v1（任务规划初始化）→ Task 1 内容
    ↓
┌────── 循环 ──────────────────────────────────────┐
│  阅读 Task → 底部输入框区域                       │
│   • 直接「下一步」→ 推进                          │
│   • 提问 → Director Agent 决策（6 种 action）     │
│     - inline_answer / expand_here / insert_task   │
│     - revise_plan / note_signal / proceed         │
└──────────────────────────────────────────────────┘
    ↓ 所有 task 完成
Recap（聚合学习信号 → 更新画像）→ 解锁下一章
```

### v1 → v2 关键变化

| 维度 | v1 | v2 |
|------|----|----|
| 章节内组织 | 5–8 张 card + 3–5 道独立题 | 3–7 个 task 的渐进序列，每个 task 是一段教学内容 |
| 推进机制 | 看完所有卡片 → 答完所有题 → 完成 | 每个 task 看完 →「下一步」or 提问 → Director 响应 |
| 提问入口 | 侧栏 ChatPanel + "深入理解"/"为什么错了" 两固定入口 | 底部贴顶常驻输入框，所有疑问由 Director Agent 智能路由 |
| 验证形态 | 章末固定题目作强验证 | **取消章末小测**；mastery 完全靠 task 过程中的信号（提问/停顿/明确"懂了"/顺利推进） |
| 内容生成时机 | 一次性生成全章 cards + questions | 章节进入时生成全部 task 元数据 + 仅 Task 1 完整内容；其余按需 + 预取 |
| 动态调整粒度 | 课程之间（学完更新画像影响下一课） | 章节之内（每条用户信号都可能改后续 task） |

### 游戏化机制

| 机制 | v1 | v2 |
|------|----|----|
| 节点解锁 | 完成当前解锁下一 | 不变 |
| 进度可视化 | 顶部进度条 | 不变，但进度条会因 insert/revise task 实时刷新（含"已根据你的反馈调整"提示） |
| 答题反馈动画 | 弹跳/抖动 | 弱化（无固定答题环节） |
| 完成庆祝 | 彩纸 + 推荐下一课 | 不变 |
| 连续天数 / streak | 保留 | 保留 |

## 三、课程生成策略（v2 概要）

四段式生成链路（前两段与 v1 基本一致）：

| 阶段 | 目标 | 关键变化 |
|------|------|---------|
| Outline | 课程定位 | 新增 `intent_type` 字段（concept / skill / problem / review / decision） |
| TOC | 章节框架 | 章节描述拆为 `learningObjectives[]`（2–4 条可观测目标），作为任务规划输入 |
| **ChapterPlan** ★ | 章节任务规划 | **取代 v1 的 Cards 阶段**。生成 3–7 个 task 元数据 + Task 1 内容 |
| **Director Agent** ★ | 章节内动态适配 | **取代 v1 的 Questions + ChatPanel**。每条用户输入触发，输出 6 种 action 之一 |

更多细节见：[v2_课程生成逻辑.md](./v2_课程生成逻辑.md)

### Task 不暴露类型

不再像 v1 那样区分 card/quiz/visualization。每个 task 就是"一段教学内容"。教学策略（定义+类比 / 步骤+演练 / 对比+决策 / 案例+原理 等）由 LLM 根据 `task.goal` 在 prompt 内部自适应选择，对用户不可见。

### Director Agent 的 6 种 Action

| Action | 适用场景 | UI 效果 |
|--------|---------|---------|
| `inline_answer` | 30 字内能说清的小疑问 | 输入框上方气泡回答，不打断 |
| `expand_here` | 想深入/再举例 | 当前 task 下方追加内容 |
| `insert_task` | 前置缺口、需要补救 | 在当前后插入新 task，进度条 +1 |
| `revise_plan` | 改变学习方向（跳过/换重点） | 修改后续 task 序列 |
| `note_signal` | 仅情绪/偏好信号 | 只更新 L2 状态，无 UI 变化 |
| `proceed` | "懂了"/"继续" | 推进下一 task |

## 四、用户画像策略（v2 概要）

新增**三层画像架构**：

| 层级 | 时间尺度 | 作用 |
|------|---------|------|
| L1 长期画像 | 跨课程 | 现有 V3 记忆模型（stableFacts + concept/topic projections + preferences） |
| **L2 章节运行时** ★ | 当前章节 | 任务序列动态调整的依据，章节末聚合写回 L1 |
| L3 任务上下文 | 单个 task | task 历史 + 用户输入 → Director Agent 决策输入 |

### Mastery 验证的重新设计（重要）

取消章末小测后，需要更多隐式信号来支撑掌握度判定：

| 信号 | 权重 | 触发 |
|------|------|------|
| task 顺利推进（无提问） | 0.5 | "下一步"直接点 |
| 用户主动"懂了" | 0.6 | 输入框正向表达 |
| Director.expand_here | 困惑信号（mastery ≤ 0.6） | 用户要求展开 |
| Director.insert_task（补前置） | 困惑信号（mastery ≤ 0.4） | 触发补救 |
| 章节内多 task 都顺利通过该概念 | mastered 准入条件 | ≥ 2 个相关 task 都"顺利" |

**新 mastered 判定**：weighted_score ≥ 0.78 且至少 2 个 task 涉及该概念都顺利通过（无困惑信号）。比 v1 更保守，因为没有了强验证锚点。

更多细节见：[v2_用户画像维护逻辑.md](./v2_用户画像维护逻辑.md)

## 六、v2 架构特点

### 优势

| 特点 | 价值 |
|------|------|
| 学习节奏由用户主导 | 减少认知过载，提升完成率 |
| 底部输入框 + Director Agent | 提问即时响应，不再隔离"学习"和"问答" |
| 按需+预取的内容生成 | 首屏快，且能基于前一 task 的结果生成下一 task |
| 章节内动态适配 | 同一章节针对不同用户呈现不同序列 |
| 三层画像 | L2 缓冲层避免单次状态污染长期画像 |
| 取消章末小测 | 体验更连贯，但要求过程信号更敏锐 |

### 已知风险（v2 新增）

| 风险 | 影响 |
|------|------|
| 取消强验证锚点 | mastery 判定误差可能扩大，需要严密设计过程信号权重 |
| Director Agent 误判 | 错误的 revise_plan 会改坏后续 task；需要保守策略 + thought 字段可解释性 |
| 任务规划 v1 准度 | 章节首次生成的 task 序列可能不准，靠 adaptive loop 补救；首版需观察"重生成/插入次数" |
| 预取 task 失败 | 用户点"下一步"时 task N+1 还没生成完 → 出现等待。需要 loading 兜底 + 1.5s 阈值 |
| localStorage 数据膨胀 | task 历史 + L2 状态比 v1 大；需要章节完成后压缩归档 |

### v1 遗留风险（v2 仍在）

阈值经验值、偏好只升不降、概念别名表小、跨设备同步缺失、前端测试不足——这些需要并行解决。
