# 文档索引

这份索引把文档分成四类，避免把历史计划当成当前需求。AI 或开发者请按优先级读取：

1. **当前事实**：先读当前架构速览和产品功能交接包；它们与代码冲突时，先修文档或修代码，不能让两者长期分叉。
2. **长期规格**：V2 三份架构文档描述目标架构和阶段边界，用于理解设计意图；若与当前实现冲突，以交接包为准。
3. **长期参考**：调研和课程质量计划保留可复用结论，但带日期，需结合当前架构判断。
4. **历史材料**：只作背景，不得驱动当前实现。

## 维护规则

- 契约、核心路径、模块边界变化：更新根 `README.md` 和当前事实交接包。
- 长期规格被实现或推翻：保留原文，新增当前事实说明，不直接改写成“历史”。
- 新调研、质量计划：进入 `reference/`，标题或文首保留日期。
- 新历史计划、评审、设计稿：进入 `history/` 对应子目录，不放在 docs 根目录。
- 运行 `npm run docs:check` 检查索引和链接。
