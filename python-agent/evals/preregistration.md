## 1. 研究问题与假设

- **RQ**：在固定生成模型（`ark/deepseek-v4-1-flash`，litellm 网关）下，改进版生成链路（prompt/证据策略/结构约束的候选改动，下称 **T**）相对基线（真实仓库 HEAD `dbf570a` 的现行链路，下称 **C**）是否产出更高质量的课程？
- **H1（主假设，双侧）**：T 对 C 的成对偏好胜率 `p ≠ 0.5`（评审团+位置交换裁决，见 §3）。预期方向 p>0.5，但检验双侧。
- **H0s（安全假设，单侧非劣）**：T 的事实溯源率不低于 C 超过 5 个百分点；T 的单课程成本不超过预算（§4）。
- 质量的操作定义 = `rubric.md` 五维度（事实准确 0.30 / 对齐 0.25 / 深度迁移 0.20 / 认知负荷 0.15 / 先修连贯 0.10）+ 事实否决门槛。偏好裁决提示词必须注入完整 rubric 与 spec/persona 上下文。

## 2. 设计总览

- **样本**：`golden_set.json` 全部 60 条 spec（20 主题 × 3 难度），每条 spec 生成一对课程（C 与 T），共 **60 配对、120 门课程**。每对绑定同一 persona（spec 内 `persona_id`）。
- **生成控制**：C 与 T 使用同一生成模型、同一网关、同一生产温度参数；每对 1 次采样（生产真实性优先，不做多采样平均）；记录 request id / seed（如网关支持）/ 时间戳 / token 用量 / 搜索调用数。
- **盲法**：评审输入剥离一切系统标识（模型名、prompt 版本号、生成时间、水印式措辞）；每对随机标记为"课程甲/课程乙"，随机序列由固定种子（seed=20261125）生成并存档。
- **评审团（异构 judge，均与生成器 deepseek 家族不同）**：
  | judge | 家族 | 角色 |
  |---|---|---|
  | `funcloud/claude-opus-5-5` | Anthropic | 评委 1 |
  | `openai/gpt-6-sol` | OpenAI | 评委 2 |
  | `bailian/qwen4-max` | Qwen | 评委 3 |
  - 利益冲突规则：若 T 的改动本身由某 judge 同家族模型参与撰写（如用其改写 prompt），该 judge 在涉及该改动的比较轮次中**回避**，评审团降为 2 人并启用 §3.4 的降级规则。
  - judge 温度取各自最低可用值；提示词版本冻结；原始输出全量存档。

## 3. 主指标：成对偏好胜率（位置交换 + 评审团聚合）

### 3.1 单 judge 单位置判定
每个 judge 对每对课程在**两种呈现顺序**（甲先/乙先）下各判一次，输出 `{winner: A|B|tie, rationale, rubric维度分(双方各5维), low_confidence: bool}`。依据 Zheng et al. (2023, arXiv:2306.05685) 的位置偏差发现，**单位置判定不直接进入统计**。

### 3.2 位置交换一致性
- 单 judge 对某对：两顺序结论指向同一课程 → 该 judge 票 = 该课程胜；两顺序矛盾 → 该 judge 票 = tie，并记 `position_inconsistent`。
- **judge 资格线**：某 judge 在全样本上的位置交换一致率 <70% → 该 judge 本轮全部票作废（降为 2 人团），并在报告中单列。70% 为操作约定，pilot 校准。

### 3.3 配对裁决
3 张 judge 票取多数：≥2 票同向 → 该对判该课程胜；否则（1:1:1、含平票分散）→ 该对 = tie。
- **胜率** `W = (wins_T + 0.5 × ties) / 60`（tie 计半分，报告口径）。
- **检验口径**：符号检验只用非平局对（§3.5）。

### 3.4 缺失与故障
- judge API 故障：重试 ≤3 次；仍失败 → 该 judge 对该对弃权，用其余 2 票裁决（2 票同向才分胜负，否则 tie）；有效票 <2 → 该对剔除出主分析并报告，敏感性分析中按"T 负"重算（保守方向）。
- T 生成失败（无法产出合法课程）→ 该对记 T 负；C 生成失败 → 该对剔除并报告（基线故障不是 T 的证据）。

### 3.5 检验方法与效应量
- **主检验**：精确符号检验（双侧，α=0.05），n=非平局对数。n=60 全非平局时：拒绝域为 T 胜 ≥39 或 ≤21（精确 α=0.0273，二项检验保守性所致）。
- **效应量**：W 及其**配对 bootstrap 95% 百分位 CI**（对 60 个配对单元重采样，B=10000，seed=20261125；tie=0.5 进入重采样统计量）。
- **可检测效应量（功效预算，诚实声明）**：
  | 真实胜率 p | 功效（n=60 非平局） | 功效（15% 平局→n≈51） |
  |---|---|---|
  | 0.60 | 0.26 | 0.30 |
  | 0.65 | 0.56 | 0.58 |
  | 0.68 | 0.74 | 0.75 |
  | 0.70 | 0.84 | 0.84 |
  | 0.75 | 0.97 | 0.97 |
  - **MDE ≈ 0.69–0.70（80% 功效）**。60 配对只能可靠检测"大改进"；若真实胜率 0.65，本设计功效仅约 0.56——**不显著≠无改进**，报告必须按此口径解释。检测 p=0.60 需约 194 个非平局对（含平局约 230 对），列为阶段1扩容选项，不在本轮承诺。
- **判显著的双条件**：符号检验拒绝 H0 **且** bootstrap CI 不含 0.5。二者冲突时判"不显著"并列入人工复查。

### 3.6 人工盲评校准（judge 分数的证据资格门槛）
- 主实验前，在**分层子样本 20 对**（难度 3 层 × 主题类型 4 类按比例抽取，pilot 6 对另计）上做人工盲评：2 名人工评审独立按同一 rubric 做成对偏好（同样位置交换、同样盲法），分歧仲裁。
- **资格线：评审团裁决与人工裁决一致率 ≥70%，或 Cohen's κ ≥ 0.6**（κ 在双方均非平局的对上计算；两指标都报告，满足其一即过线；Landis & Koch 1977, DOI 10.2307/2529310 的 substantial 档）。
- 未过线 → judge 分数**只作描述性参考，不得计为 H1 证据**；允许迭代 judge 提示词后重测校准，**最多 2 轮**；仍未过线 → 主实验降级为人工评 20 对 + judge 描述性报告，或暂停并上报。
- 与既有红线的关系：`validate_rubric_regression.py` 的 agreement≥80% 管"开放式题型启用"（产品功能闸门）；本处 70%/κ0.6 管"judge 分数能否当评测证据"（测量装置资格）。用途不同，阈值不同，互不替代。
- 校准集与主实验集**不相交**（校准用 20 对从 60 对中抽出后，主分析仍报全 60 对，但校准对的主实验 judge 票在资格确认前冻结）。

## 4. 安全指标（任一违反即触发回滚，独立于偏好结果）

### S1 事实溯源率不得下降
- **定义**：含事实性陈述的内容块中，带 ≥1 个有效 `evidenceRefs` 的块占比。有效 = 引用 id 能解析到该任务 `sourceRefs` 的真实 URL，且 URL 可达（HTTP 200/重定向后 200）。"含事实性陈述"由 judge 标注 + 程序规则（数字/版本/API 名/规范断言正则线索）双通道，分歧取并集（保守）。
- **判定**：课程级溯源率差 `d = rate_T − rate_C` 的配对 bootstrap **单侧 95% CI 下界 ≥ −5pp**（非劣界 −5pp 为先验操作约定：低于测量噪声量级即视为下降）。另报 F1 严重度3（幻觉事实）计数：`count_T > count_C` 即触发人工复查，复查确认增加 → 视同违反。
- 依据：rubric T1（事实>一切）；生成链路契约（`task_content_service.py` 证据包注入、块级 `evidenceRefs`）。

### S2 单课程成本预算
- **定义**：单课程生成成本 = Σ(token 用量 × 网关单价) + 搜索调用成本；C/T 同口径。
- **预算**：`mean(cost_T) ≤ 1.15 × mean(cost_C)` 且 `p95(cost_T) ≤ 1.30 × mean(cost_C)`（倍数为先验约定，pilot 测得基线绝对值后把绝对上限写死入实验日志）。
- judge 评审成本单列报告（评测开销，不是产品成本，不触发回滚）。

## 5. Pilot（装置验证，先于主实验）

- **样本**：6 条 spec = 2 主题 × 3 难度：`http-caching`（易误解类）+ `llm-chat-api`（快变类），spec id 见 golden_set.json。选这两类因为它们是 judge 最容易失真的场景（规范细节核对 / 版本漂移）。
- **验证项与通过线**：
  1. 端到端：spec+persona 能注入 C/T 两链路并产出合法 `task_completed` 结构（程序校验块 schema）。
  2. judge 输出可解析率 ≥95%（严格 JSON，解析失败重试后仍失败计入）。
  3. 每 judge 位置交换一致率 ≥70%（6 对上的初筛；不足则换提示词或换 judge 候选，记录偏离）。
  4. 人工校准：6 对全部人工盲评，评审团 vs 人工一致率 ≥70% 或 κ≥0.6（小样本只作 go/no-go，不作证据）。
  5. 溯源率检查器与人工审计一致率 ≥90%（抽 10 个块人工核对）。
  6. 成本测量管道产出 C 的绝对成本均值/p95 → 写死 S2 绝对上限。
- pilot 数据**不进入**主分析；pilot 暴露的 rubric 措辞问题允许修订一次（§9），修订后冻结。

## 6. 分析计划（写死）

### 6.1 主分析
按 §3 计算 W、符号检验 p 值、bootstrap CI；按 §4 计算 S1/S2。单一主检验，无多重比较问题（3 judge 已聚合为每对 1 票）。报告模板固定：W[CI]、p、非平局对数、平局率、每 judge 位置一致率、judge-人工校准结果、S1 差值[CI]、S2 比值、FAIL 任务数（rubric 否决门槛，C/T 分列）。

### 6.2 亚组分析（探索性，默认不下确认性结论）
- **难度**：beginner / intermediate / advanced（各 20 对）。
- **主题类型**：快变（5 主题 15 对）/ 易误解（6 主题 18 对）/ 稳定基础（5 主题 15 对）/ 实操技能（4 主题 12 对）。
- 每亚组报 W 与 bootstrap CI；若要对某亚组下"显著"结论，必须对该族检验做 **Holm 校正**（难度族 3 个、类型族 4 个分别校正）且校正后仍显著。禁止事后挑选亚组当主结论。
- 维度分亚组（5 维 × 难度）只作描述性热图，不做检验。

### 6.3 失败编码流程
- 范围：全部 FAIL 任务（rubric 否决）+ 非 FAIL 任务按固定种子抽 20%。
- 2 名编码员按 `taxonomy.md` 独立编码；逐类计算 Cohen's κ，**κ≥0.6 的类其失败率才计为证据**，不足者只报原始计数并注明不可靠；分歧第三方仲裁。
- 输出：类 × 难度 × C/T 的失败率表 + 严重度分级计数 + 典型判例（每类 ≥1 例原文引用）。该表是下一轮改进的输入，不是本轮显著性检验的一部分。

### 6.4 回滚规则（决策树，写死）
1. **S1 或 S2 违反** → 回滚 T，无论偏好结果。报告违反幅度与失败编码。
2. 安全通过但**主检验不显著**（含双条件冲突）→ **回滚 T**（无显著增益的改动不保留；默认基线即产品）。失败编码归档供下轮迭代。
3. 安全通过且主检验显著、W>0.5 → 采纳 T 为新基线；冻结本轮全部评测工件（spec、judge 提示词、原始判定、成本日志）归档。
4. 显著但 W<0.5（T 更差）→ 回滚 T，单列"负增益"报告。
5. 任何回滚决定允许附"有条件保留"备注（如仅某难度亚组 Holm 后显著），但**本轮不执行分群上线**——分群决策属阶段1，须另立预注册。

### 6.5 缺失数据与敏感性
- §3.4 的剔除对：主分析剔除 + 敏感性按 T 负重算，两口径都报。
- 平局率 >30% 时额外报告"强偏好口径"（tie 全剔除的 W 与检验），作为装置区分度不足的信号。

## 7. 冻结与存档

开跑前冻结：五份定义文件哈希、judge 提示词全文与版本、随机种子（20261125）、生成参数快照、S2 绝对上限（pilot 后写入）。存档：120 门课程原始 blocks+sourceRefs、360 条 judge 原始判定（60 对×3 judge×2 顺序）、人工校准原始票、编码表、成本日志。存档位置与格式由实现侧决定（跨边界需求，见报告），本预注册只要求**不可篡改、可重放**。

## 8. 已知局限（诚实声明）

1. n=60 的 MDE≈0.70：中小改进（p≈0.60–0.65）大概率测不出显著，本轮定位是"大改进筛选器 + 装置验证"，不是精细 A/B。
2. 每对单次采样：生成随机性混入配对差；用配对设计与同 spec 控制缓解，但无法分离"改动效应"与"采样噪声"，报告须注明。
3. judge 与生成器虽不同家族，仍可能共享训练语料偏差（如对某类文风的共同偏好）；人工校准是唯一外部效标，校准样本仅 20 对。
4. 偏好胜率是整体判断，可能掩盖维度级倒退（如深度升、事实降）——由 S1 与否决门槛兜底，但非事实维度的倒退只能靠维度分 descriptive 报告发现。
5. 权威 URL 会随时间漂移（快变领域尤甚）：golden set 的 `authoritativeSources` 需在每轮主实验前复检可达性并记录快照日期；内容级事实核对以开跑时的来源快照为准。

## 9. 修订流程

pilot 后允许一次修订（rubric 措辞/阈值操作约定），须记录：改了什么、为什么、对结论方向的影响评估。主实验开跑后冻结；任何事后改动在报告中以"偏离预注册"单列，且不得用于把不显著结果改写为显著。

## 修订 A0（2026-11-25，实验前，资源约束）
- 人工评审资源仅 1 人（用户）。校准改为：用户对 20 对分层子样本盲评（工作表 `python -m evals.report worksheet --n 20`），计算 **human vs judge 团多数票** 的一致率与 Cohen's κ；门槛不变（一致率≥70% 或 κ≥0.6）。局限声明：无法测人工评审间信度，judge 团内部一致率另报。
- 失败编码改为：单编码员（lead 代理）按 taxonomy.md 编码 + 用户分层抽查 ≥10 条审计；逐类 κ 不可计算，失败率只报原始计数并标注"单编码员，未经双编码信度验证"。
- 其余条款（主指标、检验、安全指标、回滚规则）不变。
