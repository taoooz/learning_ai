# 失败分类编码手册（Failure Taxonomy v1.0）

> 用途：对课程生成产物中的失败片段做**结构化编码**，支撑预注册文档（`preregistration.md`）的失败编码流程与亚组分析。编码单位是**片段**（一个内容块，或块内一个可定位的陈述/示例/题目），不是整门课程。
> 与 rubric 的关系：rubric 维度分回答"多好"，本手册回答"坏在哪、多严重"。一个片段可同时命中多类（多编码），按 §3 优先级规则排序。
> 编码输出字段：`spec_id, task_id, block_id, span(原文引用), codes[](按优先级排序), severity(取最高), coder_id, rationale(一句话), disputed(bool)`。

---

## 1. 失败类别（10 类）

### F1 幻觉事实（hallucinated-fact）
- **判定标准**：陈述了权威来源中不存在的事实：编造的 API/参数/配置项/函数签名、虚构的文献或数据、不存在的协议行为。与 F2 的区别：F1 是"从来就不对"，F2 是"曾经对、现在不对"。
- **正例**：声称 Tailwind v4 支持 `tailwind.config.js` 的 `darkMode: 'class'` 作为推荐配置（v4 推荐 CSS-first `@custom-variant`，且课程编造了不存在的 `@theme dark-mode` 指令）；编造 `requests` 库有 `auto_retry=True` 参数。
- **严重度**：**3**（默认；若幻觉出现在无关紧要的旁支且不影响主线，可降 2，须写明理由）。
- **对应 rubric**：D1=0–1，触发否决门槛。

### F2 过时事实（stale-fact）
- **判定标准**：陈述在其标注（或隐含）的历史版本下正确，但对 spec `authoritativeSources` 的当前版本已失效，且未标注版本适用范围。快变领域（LLM API、框架）高发。
- **正例**：以 Next.js Pages Router 的 `getServerSideProps` 作为 App Router 项目的默认数据获取方案且未说明适用边界；引用已被 RFC 9111 取代的 RFC 2616 缓存语义并当作现行规范。
- **严重度**：**3**（会直接导致学习者写出错误代码）/ **2**（旧做法仍可用但非推荐，未标注）。
- **对应 rubric**：D1=1–2。

### F3 引用缺失/装饰性引用（unsourced-claim）
- **判定标准**：关键事实陈述无 `evidenceRefs`，或引用 URL 与所述内容无关（装饰性），或引用指向不可达/非权威来源。与 F1 的区别：内容本身可能对，但不可溯源。
- **正例**：块中断言"GPT 类模型 temperature=0 时输出完全确定"，无引用且该断言实际存疑；`evidenceRefs` 指向一篇与缓存无关的营销博客。
- **严重度**：**2**（关键事实无源）/ **1**（次要细节无源）。
- **对应 rubric**：D1 扣分 + 安全指标"事实溯源率"的直接来源。

### D1s 解释浅表（shallow-explanation）
- **判定标准**：核心概念只有定义复述或操作清单，无机制层（为什么）、无边界条件（何时不适用）；或用同义反复填充篇幅伪装深度。
- **正例**：讲条件概率全程只给公式 P(A|B)=P(A∩B)/P(B) 与一道代入题，不解释"样本空间收缩"的直觉，也不给基率忽视的反例。
- **严重度**：**2**（核心概念浅表）/ **1**（次要概念浅表）。
- **对应 rubric**：D4=1。

### S1 脚手架断裂（scaffold-break）
- **判定标准**：任务内难度陡增无过渡：样例→抽象之间缺中间步、复杂流程无分步呈现、练习难度远超已演示内容（"演示加法、练习乘法"）。
- **正例**：入门递归课演示了 factorial 后，练习题直接要求实现带 memoization 的斐波那契且未铺垫 memoization。
- **严重度**：**2**（主线断裂）/ **1**（支线练习过难）。
- **对应 rubric**：D3=1–2；若同时缺先修铺垫，加编 P1。

### A1 评估错位（assessment-misalignment）
- **判定标准**：评估/自测/interactive 题的认知层级或主题与 learningGoal 不一致：目标应用层、评估记忆层；或题目考的 conceptKeys 不在目标内；或题目本身有歧义/无正确答案。
- **正例**：目标"能排查 CORS 预检失败"，自测题是"CORS 的全称是什么"；参数演示 interactive 的"正确答案"与规范行为不符。
- **严重度**：**3**（题目答案错误——会强化错误图式）/ **2**（层级错位）/ **1**（题目歧义但可挽救）。
- **对应 rubric**：D2=1–2；答案错误同时编 F1。

### P1 先修断裂（prerequisite-gap）
- **判定标准**：使用了超出 spec `expectedPrerequisites` 与 persona 已确认知识、且使用前未铺垫的概念；或违反 `skipBasics`/`excludedTopics` 系统性重讲已掌握内容。
- **正例**：给入门画像讲哈希表时直接使用"均摊复杂度"且未解释；给 skipBasics 含"git 日常操作"的画像用两个块重讲 commit/add。
- **严重度**：**2**（关键概念未铺垫，主线受阻）/ **1**（次要概念未铺垫或轻微重复）。
- **对应 rubric**：D5=1–2。

### R1 冗余堆砌（redundant-padding）
- **判定标准**：同一信息无新增视角地重复（跨块复述、图文逐字重复——Mayer 冗余原则）；与目标无关的背景填充（语言发展史八卦、凑字数的"重要性"论述）；key_point 与 markdown 逐句重复。
- **正例**：三个块分别用"很重要/非常关键/务必重视"开头重复同一结论；example 的 content 与 takeaway 逐字相同再复述一遍正文。
- **严重度**：**1**（局部冗余）/ **2**（冗余占任务篇幅 ≥30%，挤占有效内容）。
- **对应 rubric**：D3=1–2。注意 rubric T5：样例+机制双重表征**不算**冗余。

### L1 认知超载（cognitive-overload）
- **判定标准**：超出 persona 负荷阈值的呈现：单块新术语密度超限（入门>3/中级>5/进阶>8，操作约定）、未定义术语直接使用、超长无分段块（入门>600字/中级>900/进阶>1200）、多列宽表轰炸。与 R1 的区别：R1 是"重复的多余"，L1 是"新信息的一次性倾倒"。
- **正例**：入门第一课单块同时引入 call stack、stack frame、base case、recursive case、tail call 五个术语且均未定义。
- **严重度**：**2**（主线块超载）/ **3**（全任务系统性超载，该 persona 基本无法完成）/ **1**（局部）。
- **对应 rubric**：D3=0–1。

### E1 示例失真（example-distortion）
- **判定标准**：示例代码不能运行/输出与声称不符；示例情境与真实实践脱节（生产中不会这样用的"玩具写法"被当作最佳实践）；示例数据造作到掩盖关键现象（如用 0.5+0.25 演示浮点误差——恰好精确，掩盖了问题）。
- **正例**：声称 `0.1+0.2` 输出 `0.30000000000000004` 的代码块实际打印的是格式化后的 `0.3`；用 `Math.random()` 演示"可复现的随机抽样"。
- **严重度**：**3**（示例输出错误——学习者会照抄并困惑）/ **2**（情境失真但代码正确）/ **1**（数据造作削弱说服力）。
- **对应 rubric**：D1（输出错误）或 D4（情境失真）；输出错误同时编 F1。

### T1 空泛 takeaway（vague-takeaway）
- **判定标准**：takeaway/小结是口号或同义反复，不含可带走的具体结论、边界或下一步动作；"多练习/很重要/注意细节"式短语；或 takeaway 与正文结论不一致。
- **正例**：`takeaway: "递归是强大的工具，多加练习就能掌握"`（无信息量）；`takeaway: "记住 CORS 很重要"`。
- **严重度**：**1**（默认）/ **2**（全任务所有 takeaway 均空泛，检索练习锚点缺失——Dunlosky 意义上的练习测试无法落地）。
- **对应 rubric**：D4=1–2；`TaskBoundaryPrompt.takeaway` 空泛还会污染前序衔接（D5）。

## 2. 严重度标尺（跨类统一）

| 级 | 含义 | 处置 |
|---|---|---|
| **3** | 毁伤性：传播错误事实/错误答案，或使该 persona 无法完成学习 | 触发课程级 FAIL 复核；改进版出现任何 3 级失败必须在报告中单列 |
| **2** | 结构性：损害主线学习效果但可修复 | 计入失败率主指标；亚组分析按类×难度聚合 |
| **1** | 局部性：降低质量但不阻断学习 | 计入失败率，权重低于 2/3（报告时分级计数，不合并成单一数字） |

## 3. 多编码与优先级规则

1. **允许多编码**：一个片段最多 3 个码，按下列优先级排序（因果上游优先）：
   **F1 > F2 > E1(输出错误) > A1(答案错误) > F3 > P1 > L1 > S1 > A1(层级错位) > D1s > R1 > T1**。
   理由：事实类失败是根因（错误事实会派生错误示例与错误评估），先修/负荷是呈现层根因，浅表/冗余/空泛是质量层。
2. **根因吸收规则**：若浅表（D1s）完全由先修断裂（P1）导致（因为没铺垫所以只能浅讲），只编 P1，不编 D1s；若冗余（R1）是超载（L1）的同一呈现问题的两面，取 L1。吸收必须在 rationale 写明。
3. **严重度取最高**：片段 severity = 各码严重度的最大值。
4. **争议处理**：两名编码员独立编码，Cohen's κ 按"码是否命中"逐类计算（Landis & Koch 1977 基准：κ≥0.6 方可将该类失败率计入证据）；不一致片段由第三方仲裁，仲裁结果入库并更新本手册判例（手册版本递增）。
5. **禁止编码的情形**：风格偏好（"我觉得这个类比不好"）不构成失败码；persona 相对性争议（对 A 画像超载对 B 画像合适）以 spec 绑定的 persona 为准，不按编码员个人口味。
6. **新类提案**：无法归入现有 10 类的失败记 `OTHER` + 描述，累计 ≥5 例同类 OTHER 时提案新增类别（走预注册的文档修订流程，不在评测中途改手册）。

## 4. 与既有脚本的衔接

- `evaluate_content_quality.py` 的结构分低（块类型缺失）不自动等于失败码——结构缺失只有造成上述某类的判定标准时才编码（如缺 example 导致 S1）。
- `validate_rubric_regression.py` 的 80% 一致性红线管"开放式题型能否启用"；本手册的 κ≥0.6 管"失败率能否计为证据"。两者用途不同，不得互相替代。
